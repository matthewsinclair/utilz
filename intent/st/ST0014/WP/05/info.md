# WP-05: AC01 end to end: the install runs with the source tree moved aside

## Objective

AC01, the row the whole thread turns on: the install RUNS with the source tree gone. Devbin's install tree is deliberately not runnable (D33); ours inverts that, so the test is that it works when the source is removed, not that files arrived.

## As built

11 tests in `opt/utilz/test/install_e2e.bats`. `setup_file` copies the checkout to a temp path with `cp -a` (mtimes preserved, so the publish build is a cargo no-op at 0.03s rather than a cold compile), commits inside the COPY so the dirty gate is satisfied without touching hv's tree, publishes through the real `utilz install`, and then **removes the source**. Everything below runs against an install whose source no longer exists.

The first test is a guard on the guard: if `setup_file` failed to remove the source, every test after it would pass while proving nothing.

## What runs from the install with no source

`utilz version` (and it reports `installed at <prefix>`), `utilz list` naming all fifteen, `utilz help mdagg`, `utilz doctor`, `<prefix>/opt/prez/prez` with no crate present, and the manifest verifying against itself.

**And `cleanz --detrope`, which is the crown jewel.** It reads `opt/cleanz/data/trope-indicators.txt` -- exactly the file D2's original inclusion list would have dropped. Had the owned set stayed at `<n>`, `<n>.yaml` and `README.md`, cleanz would have arrived, dispatched, and found nothing: a broken install that looks installed.

## Two findings the end-to-end caught that nothing before it could

**`utilz doctor` exits 1 from a fresh install, and it is RIGHT to.** A temp prefix is not on `$PATH` and doctor says so. That is AC16 / WP-12's territory, not a defect. The test asserts the four substantive checks and that the PATH warning is the ONLY issue, rather than asserting rc 0 -- which would have meant either weakening doctor or pretending an unconfigured PATH is fine.

**Eight `opt/*/README.md` ship a literal `/Users/matts/Devel/prj/Utilz`.** Two occurrences each, in a Development section, historical drift from an older generator -- the current `tmpl/README.tmpl` ships the literal string `$UTILZ_HOME` and is clean. **Zero CODE files name any absolute home path**, which is what makes the install genuinely relocatable, and that is the assertion the suite pins. The READMEs get their own issue rather than an exception list here, which would rot the first time someone fixed one.

## Why the source is a copy rather than the real tree

Moving hv's working checkout aside is not available: three concurrent writers, and the risk is unbounded against a test's benefit. The copy closes the reach-back-to-my-own-source case completely. The case a copy cannot see -- a path hardcoded to the REAL tree, which survives because the real tree is still there -- is closed by the two grep assertions instead.
