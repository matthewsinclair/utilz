# ST0020: prez: a theme name defined twice on the search path refuses, when a caller asks

## Objective

When a caller sets `PREZ_THEME_DUPLICATES=refuse`, prez refuses a theme name that is defined in more than one place on its search path, and names every definition, instead of letting search order choose silently. With the variable unset, prez resolves a theme name by first match, exactly as it does today.

## Context

## Why

Gtools' `gtools present` assembles prez's theme search path from its own themes and from every client folder's themes, so one theme name can be defined twice. prez would take whichever definition sorted first and say nothing. Gtools' AC05 (its ST0010) requires such a name to refuse and name both directories, instead of letting search order choose silently.

hv ruled (b): an opt-in check in prez, which the Gtools shim turns on, leaving first match for every other caller. gtools-vc relayed the ruling on 2026-09-14, and the relay was held until hv's own word arrived, per the standing directive that a relayed ruling is not the ruling. hv gave it directly to utilz-cc in session the same day: "Yes, (b), next release". hv also put this thread ahead of ST0019's design.

**2.9.0 had already shipped** when the request arrived, so this thread ships in the next Utilz release.

**This thread names the requester, and prez does not.** `intent/` never ships, and the zero-knowledge ruling binds prez's code, comments, tests and docs.

## The design in brief

- A new variable, `PREZ_THEME_DUPLICATES`, holds a policy: unset, empty or `first` keeps first match; `refuse` refuses a resolved name with more than one definition; any other value is refused by name.
- A definition is a `<dir>/<name>/theme.css` or a `<dir>/<name>.css` on the search path. One file reached twice is one definition, and a built-in is not a definition.
- The refusal exits 2, carries its own prefix, and lists every definition with its directory and the mechanism that put that directory on the path.
- The shared resolver takes the policy as a parameter over one walk. prez reads the variable at its edge, and showreel passes first match.
