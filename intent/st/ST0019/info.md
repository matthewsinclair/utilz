# ST0019: Release Utilz through dvb build release and a Homebrew tap, like Intent

## Objective

A Utilz release is cut by devbin's release core, the one the fleet shares, and Utilz installs and upgrades through a Homebrew tap, the way Intent does. This thread builds Utilz's parts: the release declaration and its gates, the version and CHANGELOG conventions, the keg as an install tree that brew owns, the formula, and the step that moves the formula to each new tag (design.md).

## Context

hv, 2026-09-14, raised directly to vc: bring Utilz's releases into line with the other devbin projects, and "brew-ify utilz so that it works just like intent". Until then every Utilz release was a hand-made commit, tag and push, and the GitHub release object lapsed between v2.2.0 and 2.9.0.

Scope, as hv ruled it on 2026-09-14: the shared release core (pre-flight, stamping, dating the CHANGELOG, commit, tag, push and the release object) is Devbin's, with Utilz its first user, and this thread builds Utilz's own parts. The six open questions of the brief are answered in design.md, each with its ruling. Cutting 2.9.0 by hand taught that `git tag -F` strips `###` headings unless `--cleanup=whitespace` is passed; the core does so (design D6).

Roles: cc builds, vc reviews and verifies, and hv rules, pushes and cuts the release.
