# ST0030: Lights-out release: one command from cut to tap

## Objective

One command, `bin/devbin release --patch --yes` (or `--minor`, `--major`), takes Utilz from a green main to a published release with Menuz.app attached and the Homebrew tap updated, with nobody at the terminal after it starts. Apple's notarisation is the only wait.

## Context

hv, 28 Oct 2026, after cutting 2.14.5: the cut is bitty next to Ccusage's `tools/release`, which bumps, checks, tags, pushes, waits for CI and publishes the tap in one command. 2.14.5 took a confirm prompt, 1514s of gates that re-ran the suites the dry run and the twins had already passed, and four steps by hand after the cut (a worktree at the tag, `macos app-sign`, `app-notarize`, `publish`, then `tools/formula publish`).

hv's rulings, directly to vc on 28 Oct: (a) an `after:` line runs the steps after the cut, reversing hv's ruling of 2026-09-21 (ST0019 WP-05) that no release hook runs `tools/formula publish`; (b) the release gates are `check all` only, with `test estate` dropped, since the dry run and the twins run the suites before a cut; (c) the cut is confirmed by `--yes`, which devbin's release core already takes.

Devbin's core already has `--yes` and `after:`. Its after step runs every line even when one before it failed, so the steps go in one script, `tools/post-cut`, which stops at the first failure: a formula pushed before Menuz.app.zip is attached gives every new install a failing `menuz install` (docs/releasing.md).
