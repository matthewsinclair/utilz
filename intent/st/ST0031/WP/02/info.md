# WP-02: CI tuning, banked for the sweep's push: a cargo cache, test-linux's roster derived, and a timeout on the rust job

## Objective

Utilz's rust job keeps its dependencies between runs and stops at 25 minutes, and both test jobs run one roster derived from `utilz list`: a cargo cache pinned by commit that holds dependencies only, never the workspace's own crates; `timeout-minutes: 25` (issue 0131's point 5), where GitHub's 360 is the only bound today; and `tools/ci-suites`, in place of test-linux's typed list and test-macos's own, so the next utility is tested on both legs. It is banked, and lands with ST0031/01 in the sweep's push, and CI proves it.

## Measured

dc, 31 Oct 2026, from runs 41127538028 (2.14.8's tag, both attempts), 41140741047 (main's push at 1434e764) and 41127529723 (main's push at f2021ddc), read through GitHub's jobs API and the job logs, and checked by utilz-vc where it sampled them.

- **A green Rust leg takes 5.5 to 7.1 minutes on ubuntu and 11.1 on macOS.** The stalled macOS leg of issue 0131 held its leg for 22.9 minutes until it was cancelled by hand. tests.yml sets no `timeout-minutes`, so GitHub's 360 is the only bound.
- **Each Rust leg compiles its dependencies twice**, once for `cargo build --release` and again for `cargo test --release`. The release build alone took 33.6 s on ubuntu and 62 s on macOS, and macOS's test build 64 s more. No workflow caches cargo's output.
- **test-linux runs a roster typed into tests.yml**, while test-macos derives its own from `utilz list`. Today `bin/utilz list` names exactly the typed roster plus prez, so deriving changes nothing now and covers the next utility on both legs.
- **Homebrew made no auto-update** before any install in either macOS job on the image macos-26-arm64 of 26 Oct (run 41127538028's Test on macOS and Rust (macos-latest)): its first output came 2.7 s, 0.5 s and 3.6 s after each install began.
- **The clippy job takes 0.3 minutes.**

## The change, as utilz-vc ruled on 31 Oct

1. **A cargo cache in the rust job**: `Swatinem/rust-cache`, pinned by the commit its v2.9.2 tag names, 6323deb102c322ba6fcbdcafc7e3dddab59af2b6, with the version in a comment, `workspaces: opt/prez/crate -> target` and `key: ${{ matrix.os }}`. It keeps dependencies only, so the workspace's own crates always build fresh.
2. **One roster**: `tools/ci-suites` runs `utilz test` for the dispatcher and for every utility `utilz list` names except prez, through the tree's `bin/utilz`, stopping at the first failure and refusing an empty list. Both test jobs call it. Its header holds why prez is the rust job's, corrected from test-macos's old comment: the rust job installs node 26, ffmpeg, poppler and a display for prez's suites, and the clippy job lints every crate.
3. **`timeout-minutes: 25` on the rust job** (issue 0131's point 5), with the durations above in its comment.
4. **Dropped**, by utilz-vc's rulings: `HOMEBREW_NO_AUTO_UPDATE`, measured as a no-op, since a line that changes nothing goes; and "clippy once", which saves seconds and no wall clock, while the clippy job lints every crate that `find opt/*/crate/Cargo.toml` discovers and AT09 lints prez's alone.
