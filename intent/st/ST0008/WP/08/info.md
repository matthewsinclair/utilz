# WP-08: utilz todo <-> intent todo mutual guard (utilz side)

## Objective

Make `utilz todo` and `intent todo` mutually non-clobbering across the shared `todo.md` format. `utilz todo` stamps a `generator: utilz todo` ownership marker on every write, and refuses to overwrite a file owned by a different generator (eg `intent todo`) -- but only when Intent is actually present, so utilz stays a zero-dependency standalone tool that runs silently and never fails anywhere Intent isn't. This is the utilz half of the symmetric contract Intent shipped in 2.16.1 (`bin/intent_todo:guard_foreign_todo`).

## Deliverables

- Stamp `generator: utilz todo` into the frontmatter emitted by the single writer (`write_file`), alongside `title:` / `history:`. Unconditional -- independent of Intent's presence.
- A `guard_foreign_todo` seam mirroring Intent's, called at the top of `write_file`: proceed silently when the file is absent, has no frontmatter, has frontmatter without a `generator:` (utilz's own pre-marker `title:`/`history:` file), or is marked `generator: utilz todo`; otherwise the file is foreign.
- Intent-aware gating on the foreign branch only: refuse (clear error + non-zero exit) only when BOTH `command -v intent` succeeds AND the **target file's own directory tree** contains a valid Intent project (`intent/.config/config.json`, walking upward from `dirname($TODO_FILE)`). Deliberately anchored on the file, not cwd (this diverges from Intent's cwd-based `find_project_root` on purpose): the guard's question is "does the file I'm about to overwrite belong to an Intent project?", so pointing `--file` at another project's `intent/todo.md` from outside still triggers it. Otherwise proceed and re-stamp as utilz. No emissions when Intent is absent.
- Default-path creation guard (follow-up): refuse to CREATE a fresh default `./todo.md` inside an Intent project (same `_intent_present` + `_in_intent_project` gates, plus a `DEFAULT_PATH` flag). Closes the first-use gap where a bare `utilz todo` littered a `todo.md` in an Intent project; explicit `--file`/`-g`, existing utilz files, read-only queries, and non-Intent dirs are unaffected.
- BATS coverage in `opt/todo/test/todo.bats`: stamp present; foreign-refusal inside an Intent project (with a stubbed `intent` on PATH); foreign-proceed outside a project; own / legacy / fresh pass-through; default-path creation refused in an Intent project; existing utilz file in a project still works.
- Docs: the ownership contract noted in `help/todo.md` and `opt/todo/README.md`.

## Dependencies

- Builds on WP-01..07 (the shipped `todo` utility). No new WP dependencies.
- Mirrors the Intent-side guard in Intent 2.16.1 (`bin/intent_todo`), but takes **no runtime dependency on Intent** -- utilz only reads the target file's frontmatter, plus a silent `command -v intent` and an upward `intent/.config/config.json` check.
