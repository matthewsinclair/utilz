The Emacs bridge cannot reach `todo`'s verbs. `utilz--build-cmdline` (`static/emacs/utilz.el:96`) builds `utilz <name> <declared flags> <extra flags> <path>`, where the extra flags are what a prefix argument (`C-u`) prompts for. The extras therefore land BETWEEN a declared flag and the path it takes. `todo` declares `input: file` and `flags: [--file]`, so entering `done 2` at the prompt builds `utilz todo --file done 2 <path>`, and todo exits 1 with `Unknown command`. This was found and documented when todo was restored to the menu (`7695060`, 2026-09-03). The refusal is loud, which was the better of the two failures then available, and the capability is there: `utilz todo --file <path> done 2` works from a shell.

THE FIX: the path follows the declared flags, and the extras come last: `utilz <name> <declared flags> <path> <extra flags>`. A declared flag that takes the path keeps it, and nothing else in the menu changes meaning, because every declaring utility accepts options after its path, read from each parser:

- `expz` and `mdagg`: a `while`/`case` loop that takes options anywhere (`opt/expz/expz:81`, `opt/mdagg/mdagg:339`).
- `pdf2md`: Python argparse, which accepts optionals after the positional (`opt/pdf2md/lib/pdf2md.py:452`).
- `prez`: the index loop in `args.rs` takes flags anywhere after the verb (`opt/prez/crate/src/args.rs:156`).
- `cleanz`: stdin and no path, so its form does not change.
- `todo`: `--file <path> done 2` works (measured in `7695060`).

Without extras the command is byte-identical to before, so `bridge.bats`'s probe of the form every declaring utility accepts is untouched.

TEST: the elisp side is covered by `static/emacs/e2e-smoke.el`, run by hand (`UTILZ_HOME=$PWD emacs -Q --batch -l static/emacs/e2e-smoke.el`). A new check there asserts that the prefix-argument form for todo keeps `--file` and the path adjacent with the extras last. It is red against the current builder and green after the fix.
