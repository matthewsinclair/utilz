## What

vc, 19 Oct 2026, after utilz-dc's note: menuz.bats and macos.bats define their own `setup()`, so test_helper.bash's `setup()`, and with it 0082's `isolate_tool_homes`, never runs for them. utilz-ic's check, the same day, at `c918dec`:

- **What `isolate_tool_homes` sets** (`opt/utilz/test/test_helper.bash:112`): `UNISON` into the per-test dir; `UTILZ_GPG_HOME` unset and `GNUPGHOME` at a path that cannot be made; and git's commit and tag signing off through `GIT_CONFIG_COUNT` (`no_git_signing`). It does not set `XDG_DATA_HOME` or `XDG_CACHE_HOME`.
- **What menuz's suites run that reads those settings.**
  - Neither suite, nor `menuz`, nor `bin/.devbin/cmd/macos` runs unison or gpg.
  - `run_doctor`'s dependency sweep, called four times in menuz.bats (`:190` to `:209`), checks only that each dependency is present, with `command -v` or `check_app` (`common.sh`, `dependency_present`); it runs none of them.
  - Neither `menuz` nor devbin's macos reads `XDG_DATA_HOME` or `XDG_CACHE_HOME`.
  - **One reader: git.** menuz.bats's `source_home` (`opt/menuz/test/menuz.bats:130` to `:132`) makes a fixture repository and commits to it. Its `setup()` points `HOME` and `XDG_CONFIG_HOME` at the test's own dirs (`:24`, `:25`), so the user's `~/.gitconfig` is not read. git still reads `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_COUNT` and the system config from the environment the suite inherits.
  - macos.bats runs no git.
- **Measured.** A temp HOME and XDG_CONFIG_HOME as menuz.bats sets them, plus `GIT_CONFIG_GLOBAL` naming a config with `commit.gpgsign = true` and a recording `gpg.program`: the fixture's `git commit` called that program (`--status-fd=2 -bsau t <t@t>`) and failed, rc 128. Without `GIT_CONFIG_GLOBAL`, as this Mac's environment and its system config (`/opt/homebrew/etc/gitconfig`, `credential.helper` alone) have it, nothing was called. So it is not reached here or on CI today. On a machine whose environment signs, menuz.bats would ask the user's gpg to sign, with `GNUPGHOME` as inherited, which is 0082's class.

## Design

utilz-ic, 19 Oct 2026. Size: XS.

1. **menuz.bats's `setup()` calls `isolate_tool_homes`** once its per-test dir exists, as test_helper.bash's own comment asks of a suite with its own `setup()` (`:44` to `:47`). That brings `no_git_signing`'s `GIT_CONFIG_COUNT` entries, which take precedence over every config file, and the fail-closed `GNUPGHOME`, into every menuz test.
2. **macos.bats is left as it is.** It runs no git, gpg or unison, and its own setup points HOME and the state dir at the test's dirs. The issue says so rather than adding a call that guards nothing.
3. **The test, red first.** It goes in menuz.bats, beside `source_home`. `GIT_CONFIG_GLOBAL` names a config that signs every commit with a recording `gpg.program` in the test's dir. `run source_home`, then the recorder is asserted empty first, then `assert_success`. On main the commit calls the recorder and fails, so the test fails at its own first assertion, that the recorder was not called, rather than inside the helper. The test sets its own `GIT_CONFIG_GLOBAL` inside the test alone, after `setup()`.
4. **No version bump, no CHANGELOG line.** Only a test file changes, and nothing shipped behaves differently.
5. **Runs,** each booked: the red on main, then the green, with menuz.bats whole under bash 3.2 and bash 5.

### Amendment

6. **macos.bats calls `isolate_tool_homes` too (replaces point 2).** One call costs nothing, and what it closes is the override itself: a suite with its own `setup()` that skips the helper's isolation. So both suites' `setup()` call it once the per-test dir exists. The red stays as measured, in menuz.bats. Both suites run whole, light and booked, under bash 3.2 and bash 5, and this lands after utilz-cc's 0084.

7. **A guard, so a later suite cannot do it again (vc, on dc's recommendation).** One test goes in `opt/utilz/test/isolation.bats`, beside 0088's teardown guard and in the same shape: every `*.bats` under `opt/` that defines its own `setup()` calls `isolate_tool_homes` in it. Today two suites define one, `opt/menuz/test/menuz.bats` and `opt/menuz/test/macos.bats`, and neither calls it, so on main the guard fails naming both, at its own assertion. Points 1 and 6's two calls make it pass.
