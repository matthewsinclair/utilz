Found by ic in the docs sync of 24 Nov 2026 (hv decision 21), and fixed on vc's word (hv decision 23).

## What is wrong

1. `macoz setpicfor --pattern <pat>` stores the pattern and prints it with `--verbose`, but `--all` never uses it (`opt/macoz/macoz:146`, `196-203`, `247`). The search always looks for `icon.*`, `folder.*` and `<dirname>.*` (`259-270`). The option has never had an effect, and nothing tells the user so. Since the docs sync, help/macoz.md:57 says it has no effect.
2. The check for fileicon runs before the mode is known (`231-237`). So a `--dry-run`, which never calls fileicon, refuses on a Mac without it. Since the docs sync, help/macoz.md:42 says so.

## The fix

1. Make `--pattern` work, as hv chose over removing it (hv decision 25). With `--all`, its value names the images that setpicfor looks for in each subdirectory, in place of the built-in names (`icon`, `folder` and the directory's own name).
   - The value is a list of shell globs separated by `|`, eg `'cover.*|art.*'`. Each glob is matched against the file name of each image.
   - setpicfor tries the globs in the order given. Where one glob matches more than one image, it takes the first in name order.
   - Only `png`, `jpg` and `jpeg` files count, in lower or upper case, as for the built-in names.
   - Without `--all`, a `--pattern` is refused, exit 1, since one directory takes the image it is given.
2. Check for fileicon only when the run will call it, so a `--dry-run` previews without it.

## The proof

Four new tests in `opt/macoz/test/macoz.bats`, each red at the base:

- with `--pattern`, a directory takes the image the pattern names in place of a built-in name, and a directory with only a built-in name is skipped;
- the globs are tried in order, and only images count;
- `--pattern` without `--all` is refused;
- a `--dry-run` with fileicon hidden from the PATH succeeds.

The existing test that a real run refuses without fileicon stays green.

Resolution: Fixed at a9feb66d, which vc checked by its change: with --all, --pattern names the images that setpicfor looks for (hv decision 25), and a --dry-run needs no fileicon. Proved by run 2FHBH1 (log runs/run-20261125T085049Z.log): the four new tests were red at the base, and macoz.bats passed 21 of 21 under bash 3.2 and bash 5.
