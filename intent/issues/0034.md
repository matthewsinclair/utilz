## Summary

`utilz todo done --prune` reports the wrong number. It archives every DONE item and then says `todo: pruned 0 item(s) to <history>`, whatever it pruned. `cmd_prune` clears the DONE bucket, calls `write_file`, and only then reports `$C`. `write_file` recounts the buckets with `_counts`, so `C` is already 0 when the message reads it. The line has read this way since the utility was added (`03ccded`, 2026-07-03, ST0008), and no test asserts the count.

Found by vc on 2026-09-14 while demonstrating issue 0033: two items were pruned, the archive held both, and the message said `pruned 0 item(s)`.

## Fix

Take the count before the bucket is cleared, and report that. A bats test, red first, prunes two DONE items and requires the message to name 2.

## Severity

Low. The archive is right and the message is wrong. A report of zero reads as nothing having happened, which is the one thing a prune report exists to rule out.
