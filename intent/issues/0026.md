## Summary

`run_doctor` announces `[6/7] Checking external dependencies...` (`opt/utilz/lib/common.sh:630`) and collects what is missing into an array, but prints the verdict -- `All required dependencies installed`, or the `Missing dependencies:` warning and its install lines -- only at `:753-776`, after `[7/7] Checking install integrity...` (`:710`) has printed its own result. **So the dependency verdict reads as step 7's.** Found by vc on 2026-09-14 in the pre-release check.

## Measured 2026-09-14

With yq off `PATH`, the output runs (leading status glyphs omitted):

```
[6/7] Checking external dependencies...
yq is not installed; it is required to parse utility metadata

[7/7] Checking install integrity...
Not an install tree, so there is no manifest to check
Missing dependencies: yq

  yq (required by utilz)
    Install: brew install yq
```

With every dependency present, `[6/7]` prints nothing beneath it, and `All required dependencies installed` lands under `[7/7]`, after the install-integrity line.

## Why

Step 7 sits between step 6's collection loop and step 6's verdict block, which stayed at the end of the function.

## Severity

Low. The issue count and the exit status are right; what is wrong is where the verdict appears, which is the part an operator reads.

## Fix direction

Move the verdict block (`:753-776`) to the end of step 6, above `[7/7]`. The Done includes a test that the dependency verdict prints before the `[7/7]` header, red against HEAD.
