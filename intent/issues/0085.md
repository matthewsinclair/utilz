## What

`run_doctor`'s dependency sweep (`[6/7]`) reads each entry of `dependencies` and `optional_dependencies` as a map with a `name`, the form `docs/developer-guide.md:330` documents. An entry written as a bare string, as in `dependencies: [jq]`, reads `.dependencies[0].name` as empty, with status 0. So doctor checks a dependency with no name: `check_command ""` fails, the entry joins the missing list, and doctor reports `Missing dependencies:` with an empty name and counts an issue. The yaml's real fault, an entry that is not a map, is never named.

0080 checks each list's shape, not its entries'. critic-shell saw this in its read of 0080, and cc files it on vc's word (19 Oct 2026), low, for 2.14.1, after 0081.

## Fix, for the design to settle

Each entry's shape is read with its `name`. An entry that is not a map, or a map with no `name`, is refused by name, eg `beta: dependencies[0] is a string, not a map with a name`, and counted as an issue, and the sweep goes on. Whether a bare string should instead be read as a name is the design's to settle; the developer guide documents maps only.

## Measured

`yq` 4.54.1 on `dependencies: [jq]`: `.dependencies[0] | type` is `!!str`, and `.dependencies[0].name` and `.dependencies[0].app` each print nothing, with status 0. The report doctor makes from that is by reading, at `afd18e3`.

## Design

cc, 19 Oct 2026, at `fb5608f`, on 0080's dependency sweep, where one loop takes both lists. Size: XS.

1. **An entry is checked only if it names a dependency.** After the sweep reads an entry's `name` (`opt/utilz/lib/common.sh:898`), an entry whose name reads empty or `null` is not checked as a dependency. doctor reads that entry's type, one more `yq` call made only for such an entry, and refuses it by name. Each refusal is an issue, and the loop goes on to the next entry. The words are:
   - `<name>: <list>[<i>] is a string, not a map with a name`, for `- jq`;
   - `<name>: <list>[<i>] has no name`, for a map without one;
   - `<name>: <list>[<i>] is <type in words>, not a map with a name`, otherwise, through 0080's `yaml_type_words`.
2. **A refused entry stops the closing claim too.** As 0080's item 15 has it for a list, doctor's dependency verdict no longer says "All required dependencies installed" when an entry was refused. A second count, beside `refused_lists`, warns `N dependency entr(ies) not checked, named above`, and 0080's words for lists stand as they are.
3. **A bare string is refused, not read as a name.** The developer guide documents each entry as a map with a `name` (`docs/developer-guide.md:325` to `:345`), and reading `- jq` as a name would give the yaml a second form with no `install` line to print. That is cc's recommendation; vc rules.
4. **The tests, red first,** strict, in `opt/utilz/test/common_lib.bats` beside 0080's doctor tests:
   - `dependencies: [jq]` is named as a string, counts exactly one more issue than the same home before, and doctor does not say all dependencies are installed. On main doctor reports a missing dependency with an empty name.
   - `dependencies: [{install: brew install jq}]` is named as having no name. On main the same nameless check runs.
5. **Docs.** The developer guide's Dependencies section says doctor refuses an entry that is not a map with a `name`. One CHANGELOG line goes under Fixed.
6. **Runs,** each booked with vc: the new tests red on main's code and then green, under bash 3.2 and bash 5, in a worktree; the `utilz` suite under both; dc's kovacs leg; `install_e2e.bats` in the primary at the landing.
