## What is wrong

A utility's `--version` ends with the tool's version line, the line of the dev, opt, brew contract (T4). That line names `utilz`, not the utility. Eg `bin/arngz --version` in the dev checkout prints:

    utilz:2.14.10/arngz:2.0.0
    <arngz's description>
    utilz 2.14.10 (dev, <sha12>)

devbin's contract gives each binary of a tool the tool's one line under the binary's own name (`tool_link_line`, devbin issue 0331). Here that is `arngz 2.14.10 (dev, <sha12>[+dirty])`. So devbin's doctor cannot read a utility's copy against the line a build here carries. At acf3b792 on 26 Nov 2026, `bin/devbin doctor` failed 17 rows, one for each utility link.

devbin's doctor also reads only the first line of `--version` (`tool_copy_line`). Line one is hv's pair, by ST0015's D2: "The format is a pair on line one, detail beneath" (hv, 8 Sep). So those rows fail on line one, whatever line three says. devbin issue Icb1329b holds devbin's side.

## Fix

Two commits off main, A and then B on top of A. hv picks the route, since the pen does not reach hv's D2.

- A, route 1: the tool's line names the utility, `<util> <utilz version> (<tree>, <sha12>[+dirty])`, and stays the last line. The version is Utilz's, because a utility is built, published and released only with its tree. `utilz_version_line` takes the name, `utilz` by default, so the line keeps one formatter. The doctor's rows pass only when devbin reads that line.
- B, route 2: the tool's line is line one, the pair is line two, and the description is line three. Then the doctor's rows pass as devbin reads them now. B moves every arm that reads the pair by its place.

The line's place is one statement in `show_version`, and one helper in the tests (`version_tool_line` and `version_pair_line` in test_helper.bash).
