`utilz help use` exits 1 with "Help file not found: <keg>/libexec/help/use.md" (kovacs-sysadm's test of 2.14.4 on kovacs, which hv asked for; vc read it in the code). The dispatcher's help branch hands any name to show_help, which looks only for `help/<name>.md`, and `help/` holds the utilities' pages and `utilz.md`, so every built-in verb fails the same way, on every tree, the dev checkout included. `utilz use --help` prints its usage.

## What

Line numbers are at `60171d27`.

- `bin/utilz:97-110`: `utilz help <name>`, and its aliases `utilz --help <name>` and `utilz -h <name>`, call `show_help "$UTIL"` for any name.
- `opt/utilz/lib/common.sh:222`: show_help renders `$UTILZ_HOME/help/<name>.md`, or fails with "Help file not found: <path>" (`:247`). A built-in verb (help, doctor, list, test, version, generate, install, upgrade, use, integration, emacs) has no such page, so its answer is an internal path and exit 1, though `help/utilz.md` already documents the verbs, a section each, and `utilz help` renders it whole.
- For a name that is neither a verb nor a utility, that internal path is the refusal's only answer.
- `opt/utilz/test/dispatcher.bats:42` asserts only that `utilz help nonexistent` fails saying "not found".

## Found

kovacs-sysadm, testing 2.14.4 on kovacs for hv (27 Oct 2026); vc read it in the code and gave it to cc.

## Design

- A verb's help already has its one home: its section of `help/utilz.md`, headed `` ### `utilz <verb> ...` ``. `utilz help <verb>` renders that section alone, from its heading to the next heading of the same or a higher level, so nothing is copied. The verbs are read from those headings (the word after `utilz`), so no second list of verbs is kept.
- show_help looks, in order: `help/<name>.md`, as now; then the `utilz <name>` section of `help/utilz.md`; then it refuses.
- Rendering keeps one home: the glow, bat and cat arms move into one function, given a page as a file with stdin closed, as now, or a section on stdin from its extraction (a pipe, never the terminal).
- The refusals. A utility (its `opt/<name>/<name>.yaml` is there) whose page is missing still names the missing page: that is a broken tree, and the path is its answer. Any other name: "utilz help has nothing on <name>: 'utilz list' names the utilities, and 'utilz help' describes the verbs", exit 1, with no path in it.
- test and generate have no section of their own (`help/utilz.md:213` names them in a sentence). Each gets one under "Commands for a dev checkout", from what README already says of them (`README.md:622`, `:672` to `:678`).
- The help verb's own section heading becomes `` ### `utilz help [utility|verb]` ``, its text says a verb shows its section, and `bin/utilz:257`'s list line says the same.
- Tests, one per behaviour, in `dispatcher.bats`. No mutations: each shows on reading that it fails.
  - `utilz help use`, with glow and bat off PATH (`path_without`), prints `help/utilz.md`'s `use` section, from its heading to the line before `utilz upgrade`'s, which is absent.
  - Every `utilz <verb>` section heading in `help/utilz.md` answers `utilz help <verb>` with exit 0, its output opening with that heading's text.
  - `utilz help nonexistent` exits 1 naming `utilz list` and `utilz help`, with no path in its output (dispatcher.bats:42's assertion changes to this).
  - A utility whose page is missing names that page.
- The run, the smallest that proves it: `dispatcher.bats` whole, and `help_dispatch.bats` without AT06, under bash 3.2 and bash 5, light. AT06 runs prez's shim, which needs a build, and its one call into show_help, expz's, takes the page path AT01 to AT08 already run for every utility.
