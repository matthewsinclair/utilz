## What is wrong

`mdagg --strip-front-matter` (`-s`, or `settings.strip_front_matter` in a YAML config) removes the lines from the first `---` line of a file to the next `---` line, wherever the first one is (`opt/mdagg/mdagg:128-136`). A front-matter block is only one that opens with `---` on line 1.

So a file with no front matter that uses `---` as a divider loses text:

- with two dividers, the text between them goes, and the dividers with it;
- with one divider, everything after it goes.

A file whose line 1 is `---` with no closing `---` line also loses everything after line 1. mdagg exits 0 and says nothing, so the loss shows only in the output.

## The fix

- Strip a block only when it opens with `---` on line 1 and closes with the next `---` line.
- A file whose line 1 is `---` with no closing line keeps all its lines.
- A `---` line after the block, or in a file with no block, stays.

## The proof

Two new tests in `opt/mdagg/test/mdagg.bats`, each red at the base: under `-s`, a file with no front matter and two dividers keeps all its text, and a file with an unclosed `---` on line 1 keeps all its lines. The existing test of a real block stays green.

Resolution: Fixed at a9feb66d, which vc checked by its change: mdagg strips a block only when line 1 is --- and a later --- line closes it. Proved by run 2FHBH1 (log runs/run-20261125T085049Z.log): the two new tests were red at the base, and mdagg.bats passed 44 of 44 under bash 3.2 and bash 5.
