## Method

**The criterion.** A number is deleted when it counts the members of something that can grow (steps, checks, tests, suites, guards, lines, utilities), or names a member by its position in one, wherever it is written: in prose, a comment, a test's name, or an example's output that reports the tree's own members (`docs/design-principles.md:232`). Such a number is wrong as soon as a member is added. A number stays when it is part of what it stands beside: an identifier or a version; a format or contract value (an exit status, a port, a size, a timeout); the input a test builds or the output it asserts; a command's argument, and a comment that names it; an illustrative value in an example; or a quotation. A line that reads as well without its number loses it.

**The population, by command at a named commit, never a hand list.** `git ls-files` at the sweep's base commit, which the ledger records. The suites: every file under `opt/*/test/`, `opt/prez/crate/test/`, `opt/prez/crate/tests/`, `native/macos/Menuz/MenuzKit/Tests/` and `native/macos/Menuz/MenuzTests/`, and `tools/test-estate`, with the test items (`#[cfg(test)]` modules and `#[test]` functions) of every Rust `src/` file that carries them. The docs: `docs/**`, `help/**` and `README.md`. Every file is either read by an extractor below or named in the ledger with the reason it holds no names, comments or prose (fixture data a test reads as input, a binary); the run refuses a file that is neither. The test names are cross-checked against the names each runner prints in the booked baseline run (bats' TAP, cargo's and swift's lists, xcodebuild's log), so no runner's population falls outside the scan.

**Extraction by a parser, per language; a file that does not parse is a refusal by name, never a skip.**

- Shell and bats, extensionless scripts by their shebang: shfmt 3.14.1's own parser (`shfmt -ln bats --to-json`, or the shebang's dialect), every comment with its position, and each test's name from its `TestDecl`. Measured on `help_dispatch.bats`: it parses, and its comments come back with line and column, the shebang among them (dropped).
- Markdown: pandoc 3.12.1's gfm reader with source positions, as a JSON tree; each hit is tagged prose, inline code or fenced code (with the fence's language), since example output is read case by case and a fenced shell block's comments are comments.
- JavaScript and HTML (prez's probes under `opt/prez/crate/test/`): prettier's own parsers, which return every comment with its location.
- Rust, Swift and Lua: no comment-keeping parser is on this Mac, so a lexer per language, written to its reference for comments and literals (Rust's nested block comments, raw and byte strings, and char literals beside lifetimes; Swift's nested block comments and its multi-line, raw and interpolated strings; Lua's long brackets of any level). It proves its own cut: the pieces it cuts join back to the file byte for byte. Test names: Rust's `#[test]` function names, Swift's `@Test("...")` names (the function's name where it gives none), and the name argument of each `check` call in `plan_test.lua`.

**Detection over what the extractors return.** Numerals as whole tokens, with approximations (a tilde or "about" before the numeral); number words, from a list kept in the scan (the cardinals and the tens, hundred, thousand, dozen, couple, pair, single, both, twice, once, half); and, if vc says yes, positions: ordinals in words and figures, and a label followed by a numeral (hv's `check 14`).

**The ledger.** Every hit gets a verdict: delete, the line reworded to read without it, or keep, with its class from the criterion, and for a test's own input the line that builds it. The ledger and the scan are banked outside the tree with their hashes, never committed; vc reads the ledger before any edit and again with the diff.

**The proof that none is left.**

- The same extraction and detection run on the swept tree: every hit must match a keep row, by file and text since line numbers move, and none a delete row. The run prints how many hits it saw and how many it matched, and refuses on any it cannot match.
- Nothing else moves: every line the diff changes is a line the ledger holds a delete row for; and in the suites, each changed file with its comments and test names set aside is the same before and after (shfmt's tree, the lexers' code), so no code and no asserted output changes.
- The suites give the same results on the base and on the swept tree, read from the runs and compared test for test through the ledger's renames: a heavy booked through vc, and dc's kovacs leg on the same bytes.

**Order.** vc's read of this plan. A booked light run of `intent critic` over every file the sweep may touch, since the gate reads whole files and a finding already in one would refuse the landing. The scan and the ledger at the base commit, banked for vc's read. Issue 0117 lands before the sweep reaches the dispatch suites. The edits, in a worktree under `~/Devel/scratch/utilz-cc/`. The proof run, then the heavy and the kovacs leg. The landing by path on vc's word, the docs and the suites as separate commits, since the docs need no suite run; then the close.
