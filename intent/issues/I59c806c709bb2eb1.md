## Rulings

- hv, 2026-11-06 (devbin#0326): devbin's dev/opt/brew approach is the canonical one for every Homebrew'd tool, every project uses it with every difference removed, and the core carries it. The switch is a devbin feature: `bin/devbin use [dev|opt|brew]` and `bin/devbin install`, run in the tool's checkout, and no tool keeps a `use` or `install` verb of its own. "Every project that vendors devbin takes it the same way: Utilz, Molt and Gtools too, each adoption filed when this lands."
- hv, 2026-11-22, relayed by devbin-vc: "You have my approval to lean in to any repo and make the upgrade." devbin-cc carries the adoption into this tree, on devbin-vc's read of each plan, with each unit's own tests run at the Desk, commits by path, and no push without hv's word.
- devbin-vc, 2026-11-22: a script tool keeps its own `--version` reader (devbin's T4 reader is Rust's, and T4 has a script tool's dev line read HEAD at run time), and loses only its install and use verbs and its manifest code.

devbin's core has carried this since devbin 0.1.21 (devbin#0326; `install.switch` and `install.publish` since 0.1.22, devbin#0332), and this tree vendors devbin 0.1.28. The contract is devbin's `docs/dev-opt-brew.md`, and devbin's `docs/configuration.md` says each `install:` key.
## What is wrong

Utilz implements devbin's dev/opt/brew contract a second time, in its own code:

- `opt/utilz/lib/install.sh` (about 1900 lines), sourced by `bin/utilz` for `utilz install`, `utilz upgrade`, `utilz use` and the retired `relink`: `install_verb_install` (the publish, T2, with its own manifest, T3, and the prefix from `UTILZ_INSTALL_PREFIX`), `install_verb_use` (the switch, T5, over the link set in `~/.local/bin`, with its own shadow check) and `install_verb_upgrade`.
- `opt/prez/crate/src/switch.rs` and `tests/manifest.rs`, prez's own reading of the trees and the manifest.
- The tests that prove that copy: `opt/utilz/test/install.bats`, `install_e2e.bats`, `install_guards.bats`, `install_lib.bats` and `use.bats` (about 2800 lines), and `opt/menuz/test/install-handrun.sh`.
- `packaging/homebrew/utilz.rb` lays out its keg by hand from the tag's checkout, with its own `def install`, where devbin's T8 has one install body, `@@INSTALL@@`. Its caveats name `utilz use`.
- `bin/.devbin/config.yaml` has no `install:` block, so `bin/devbin install` and `bin/devbin use` have no utilz to publish or switch.
- README.md's trees section, `help/utilz.md` and `docs/releasing.md` name `utilz install` and `utilz use`.

One contract has two implementations, so a maintainer meets a different switch here than in every other tool, and every fix is made twice.

## Fix outline

- Declare utilz in an `install:` block:
  - its opt prefix, `~/Devel/opt/utilz`, where an opt tree already lives on this machine;
  - its link set, `utilz` and each utility it links;
  - its runtime set as `files:` places: the tracked runtime paths, and the Rust products its build makes.
- Remove `utilz install` and `utilz use`, the publish, switch and manifest code in `opt/utilz/lib/install.sh`, and `UTILZ_INSTALL_PREFIX`, with the tests that prove that copy. The plan decides `utilz upgrade` and prez's `switch.rs` on reading them: each goes, or stays as the tool's own work with devbin's trees beneath it.
- Keep utilz's own `--version` readers, which read the manifest's `line` in opt and brew and HEAD in dev (T4 for a script tool).
- The formula installs through `@@INSTALL@@`, and its caveats name `bin/devbin use`, run in the checkout.
- The docs and CHANGELOG say the same, recording the removed verbs as a ruled divergence.

## Acceptance

- `utilz install` and `utilz use` are gone. `bin/devbin install` and `bin/devbin use dev|opt|brew`, run in Utilz' checkout, publish and switch utilz's whole link set from devbin's one implementation.
- Each linked utility's `--version` prints T4's line in dev, opt and brew, and `bin/devbin doctor` passes its shadow and version-line checks.
- The formula renders from `@@INSTALL@@`, and its caveats name `bin/devbin use`.
- T10's proof passes, its brew leg after Utilz' next release.
- devbin#0326 records this issue's close.
