## What

Page numbers in prez's PDF output, switched on per deck by a front-matter setting.

## Why

Filed from Gtools on hv's instruction, 25 Sep 2026 (hv: "Page numbers should be a front-matter setting"; default ruled "off unless set"). In HTML, prez shows its live "4 / 12" counter. In print, prez hides it (`crate/src/html.rs`, the print CSS: `.gp-counter { display: none; }`) and nothing replaces it, so no PDF carries page numbers, whatever the theme.

A theme cannot fix this per deck: `FrontMatter` (`crate/src/frontmatter.rs`) knows `title`, `author`, `date`, `theme`, `theme_file`, `include` and `mermaid`, and anything else lands in `unknown`, which no theme can see. One client theme already hand-adds a CSS page counter in its own print block, which turns numbers on for every deck using that theme; copying that into each theme would fork the same concern across themes.

## Proposed

- A front-matter key, eg `page_numbers: true`. **Default off** (hv), so no existing PDF changes.
- When set, prez marks the deck (eg a class on `.gp-deck`) and its own print CSS adds a CSS counter: `counter-reset` on the deck, `counter-increment` per slide, the number on `.gp-slide::after`, placed bottom right, and none on the title slide.
- Colour and font come from the theme's existing variables (`--gp-muted`, `--gp-display`), so every theme gets numbers with no theme change.
- Once it lands, the hand-added counter in that client theme can come out.

## Known working CSS (from the client theme, verified in a real PDF)

```css
@media print {
  .gp-deck {
    counter-reset: gp-page;
  }
  .gp-slide {
    position: relative !important;
    counter-increment: gp-page;
  }
  .gp-slide::after {
    content: counter(gp-page);
    position: absolute;
    right: 4vmin;
    bottom: 3vmin;
    font: 400 0.55em/1 var(--gp-display);
    color: var(--gp-muted);
  }
  .gp-slide.title::after {
    content: none;
  }
}
```

## Settled before code (hv, 16 Oct 2026)

**This replaces hv's earlier ruling of the same day** that the number is skipped on slides with the `title` class, and cc's first reading before that, that it is skipped on the first slide. Where it differs from Proposed above, this section governs.

- **Deck default: `numbering: on|off` in front matter**, off when absent. It replaces the proposed `page_numbers` key. It is a typed `bool` on `FrontMatter`, never read out of `unknown`.
- **Slide override: `<!-- numbering: on|off -->`** on any slide, in the same comment-directive syntax as `<!-- class: title -->`. A slide with no override follows the deck. The directive is lifted out like `class:` and never reaches the artifact.
- **The `title` class has no say in numbering.** A title slide that should show no number says `<!-- numbering: off -->`.
- **Every slide uses up a page number, shown or not**, so the number printed on a page is that page's index in the PDF.
- **On/off and true/false are accepted, case-insensitively. Anything else is refused** (exit 2), at deck or slide level. The refusal names the key and the bad value, and for a slide it also says which slide. `yes` and `1` are refused too: the vocabulary is hv's, not `mermaid:`'s.
- **Print only, number only.** The live `N / M` HTML counter is untouched. A page shows its own number, with no "of N".
- **Off by default, byte for byte.** A deck with no `numbering` anywhere compiles to exactly the artifact it produced before this change, which is checked by diffing every example deck under every built-in theme against HEAD.
- **Theme variables.** Colour is `var(--gp-muted)`, which all seven built-in themes define. No built-in theme defines `--gp-display`, so the face is `var(--gp-display, inherit)`. No theme changes.
- **Implementation (to settle with dc's review):** each slide's number is decided by prez, not by a deck-wide CSS rule, and emitted on the slide (eg a data attribute carrying the number), with print CSS that shows it. Proposed's CSS-counter approach cannot express a per-slide override that still uses up a number unless every slide is counted and only some show it, which is the same thing done in CSS.
- **Proof.** Parser tests for the deck key and the slide directive (on, off, absent, invalid, and the title class saying nothing). AT21 in `crate/test/acceptance.sh` runs `prez pdf` and reads each page with `pdftotext`: deck on with slide 2 off (1, none, 3); deck off with slide 2 on (none, 2, none); deck on with slide 2 a title slide (1, 2, 3); no key anywhere (none on every page); and a bad value refused at deck level and at slide level, naming what it must.
