## What

0053's class is a refusal that `set -euo pipefail` makes unreachable. An assignment `x=$(...)` whose command fails ends the script at the assignment, so the guard after it, written to say what went wrong, never runs, and the run exits without a word. cc's triage for vc on 19 Oct (at `b853f77`) found the class in two utilities. This issue sweeps every site, and settles the two the triage left unsure by measurement. Line numbers are at `2d73b7f`.

**cleanz, two sites.** `cleanz` runs under `set -euo pipefail` (`opt/cleanz/cleanz:12`) and calls `detect_tropes` as a plain statement (`:885`), whose loop is fed by a redirect (`:459`), so errexit is live inside it.

- `:408`, `first_match=$(printf '%s\n' "$matches" | head -1)`. `head` exits after the first line. Once `grep`'s matches outgrow the pipe, `printf` dies of SIGPIPE, and pipefail makes 141 the assignment's status. `cleanz --detrope` exits 141 after printing the cleaned text, with no trope report and nothing on stderr.
- `:433`, `line_ref=$(printf '%s' "$first_match" | sed 's/^\([0-9]*\):/line \1: /' | head -c 80)`. The same death when one matching line is longer than the pipe: `head -c 80` exits, and `sed` dies writing the rest.

**utilz, three walkers of the utilities' yamls.** `bin/utilz` runs every verb under `set -euo pipefail` (`bin/utilz:9`), and each of these as a plain statement. In each, the first `yq` read of a utility's yaml discards `yq`'s stderr and has no `||`, so a yaml `yq` cannot read ends the verb at that read, before any check after it.

- `run_doctor`'s dependency sweep (`opt/utilz/lib/common.sh:801`, `dep_count=$(yq eval '.dependencies | length' ...)`), run by `utilz doctor` (`bin/utilz:118`). The report stops under its `[6/7] Checking external dependencies...` title, with no verdict. The guard at `:802`, written for output that is not a number, never runs.
- `emit_integration_tsv` (`:1386`, `has_integration=$(yq eval '.integration' ...)`), run by `utilz integration commands` (`bin/utilz:172`), which is the Emacs bridge's manifest. The TSV stops at the utility before it, exit 1, with nothing on stderr. The triage named `:1383` (`desc`, now `:1389`), but the first read is `has_integration`, three lines above it.
- `emacs_doctor` (`:1446`, the same read), run by `utilz emacs doctor` (`bin/utilz:204`). The report stops under `[2/3] Checking integration metadata...`. The triage did not weigh this one.

**utilz, one expression that fails on a yaml that parses.** `emit_integration_tsv` reads `flags=$(yq eval '.integration.flags | join(",")' ...)` (`:1392`), and `join` fails on anything but a list, absence included. So an integration block with no `flags:`, which the function's header calls the default (`:1371`), or one with `flags: --file`, ends `utilz integration commands` the same way, and the `"null"` test after it (`:1394`) never sees a null. Every shipped yaml with an integration block (cleanz, expz, mdagg, pdf2md, prez, todo) writes `flags:` as a list today, so no shipped utility trips it. The next one written without `flags:` would.

## Measured

Slot 82 (gtools-vc, light, 19 Oct 07:48Z), `yq` 4.54.1, `/bin/bash` 3.2.57 and bash 5.3.20, at `2d73b7f`:

- `yq` exits 1 on a yaml that does not parse, for every query, and says where: `Error: bad file 'bad.yaml': go-yaml load error in parser (while parsing a flow node) at L3.C1: did not find expected node content`.
- `.integration.flags | join(",")` exits 0 on `[a, b]` and `[]`. It exits 1 on a string, a map, an int, `null` and absence: `Error: cannot join with !!null, can only join arrays of scalars`.
- `.dependencies | length` and `.dependencies[0].name` exit 0 on every shape tried: a list, an empty list, a string, a map, an int, `null`, and absence. So on a yaml that parses, only `join` can fail.
- `x=$(printf '%s\n' "$m" | head -1)` and `x=$(printf '%s' "$l" | sed ... | head -c 80)` under `set -euo pipefail`: 0 of 20 trials die at 4, 16 and 64 KiB. 20 of 20 die with 141 at 128 KiB and at 1 MiB, on both bashes.
- `bin/cleanz --detrope` exits 0 with its report on 100 and 2000 matching lines (3.5 and 73 KB) and on single lines of 1 KB and 70 KB. It exits 141, with no report and nothing on stderr, on 20000 matching lines (749 KB) and on one 300 KB line, 3 of 3 each.

Not measured: `utilz doctor`, `integration commands` and `emacs doctor` on a yaml that does not parse. That follows from the first bullet and the plain-statement calls, and the red tests below measure it.

## Design

cc, 19 Oct 2026, at `2d73b7f`. Size: M. Each site refuses by name, and nothing changes for input that reads today.

1. **cleanz slices in the shell.** `:408` becomes `first_match=${matches%%$'\n'*}`. `:433` becomes `line_ref="line ${first_match%%:*}: ${first_match#*:}"`, then `line_ref=${line_ref:0:80}`. With no pipe there is no SIGPIPE, and nothing for a `|| true` to hide. The text is the same for every input that works today, except that the cut is 80 characters rather than 80 bytes, so it no longer splits a multibyte character. `:407`'s `printf | wc -l` stays, since `wc` reads everything.
2. **One helper says why yq cannot read a yaml.** `yaml_read_error <file>` in `common.sh` prints `yq`'s own first line of complaint, without its `Error: ` prefix, for a file a walker's read has just failed on. Only that failure path calls it, so a yaml that reads costs no extra `yq` call. Each walker's first read becomes `if ! x=$(yq eval ... 2>/dev/null); then <refuse>; continue; fi`, and each refusal names the utility and the reason:
   - `run_doctor` (`:801`): `error "<name>: <name>.yaml cannot be read, so its dependencies are not checked: <reason>"`, counted as an issue. The sweep goes on to the next utility, and the report reaches `[7/7]` and a verdict of `Found N issue(s)`.
   - `emit_integration_tsv` (`:1386`): `warn "<name>: <name>.yaml cannot be read: <reason>; skipping"`. This is the function's existing contract for integration values it cannot use (`:1398`, `:1402`): the TSV carries every other utility, and the bridge keeps working.
   - `emacs_doctor` (`:1446`): `<name> (<name>.yaml cannot be read: <reason>)` joins its `invalid` list, which it already reports and counts as an issue (`:1481` to `:1486`).
3. **flags reads as a list or refuses.** `:1392` becomes `if ! flags=$(yq eval '(.integration.flags // []) | join(",")' ...); then warn "<name>: integration.flags is not a list; skipping"; continue; fi`. Absence and `null` read as `[]`, the default the header promises (`:1371`), and give an empty flags column. A string, a map or a number is refused by name. The dead `"null"` test (`:1394`) goes.
4. **emacs doctor agrees with the manifest.** `emacs_doctor` reads `.integration.flags | type` beside input and output, and a `flags` that is neither a list nor absent joins `invalid`, so `utilz emacs doctor` names what `integration commands` would skip. This one is recommended rather than required by the class: without it, `emacs doctor` passes a yaml whose utility the bridge never offers.
5. **The tests, red first.** Each runs as `bin/utilz` runs it, with `set -euo pipefail;` first, since the test helper alone runs non-strict.
   - `opt/cleanz/test/cleanz.bats`: `--detrope` on 20000 lines that each match WC-02 reports `delve-and-friends` and exits 0. On one 300 KB line with one match it reports `line 1: ` with a ref of at most 80 characters, and exits 0. Red on main: exit 141, no report.
   - `opt/utilz/test/bridge.bats`, over a scratch tree under `BATS_TEST_TMPDIR` with `UTILZ_HOME` pointed at it, never at the checkout: `alpha` with a good integration block, and `beta` with a yaml that does not parse. `emit_integration_tsv` emits `alpha`'s row, names `beta` and why, and exits 0. `emacs_doctor` lists `beta` as invalid and reaches `[3/3]`. An integration block with no `flags:` emits its row with an empty fifth column, and `flags: --file` is named and skipped. Red on main: each exits 1 at the read, without a word.
   - `opt/utilz/test/common_lib.bats`, beside its other `run_doctor` tests (`:307`): `run_doctor` over the same tree names `beta` and reaches `[7/7]`. Red on main: the report ends under `[6/7]`.
6. **Docs.** `help/utilz.md`'s `integration commands` (`:210`) gains three points: a utility whose yaml cannot be read, or whose `flags` is not a list, is named on stderr and left out of the TSV, and `flags` may be absent. `emit_integration_tsv`'s header (`:1369` to `:1376`) says the same. `help/cleanz.md` needs nothing. One CHANGELOG line goes under Fixed. For vc's globalfold, one trap for `restart.md`: under pipefail, `x=$(... | head ...)` dies of SIGPIPE once its input passes the 64 KiB pipe. Slice with parameter expansion, or end the probe `|| true` where `head` stopping early is the point.
7. **Versions.** cleanz goes from 1.2.0 to 1.2.1 (`opt/cleanz/VERSION`). utilz's version is the framework's `VERSION`, which the cut sets.
8. **Runs,** each booked with gtools-vc. First the new tests, red on main's code and then green, under bash 3.2 (`/bin` first on PATH) and bash 5, in a worktree. Then `cleanz.bats` and the whole `utilz` suite under both, since `common.sh` is everyone's. Then dc's shellcheck 0.9.0 on kovacs, and `install_e2e.bats` in the primary at the landing.

**Seen, not taken.**

- `get_util_metadata` (`common.sh:97`) swallows a read that fails. It runs inside `$(...)`, where bash clears errexit, and it ends with `echo "$result"`, status 0. So `utilz doctor`'s `[5/7]` reads a yaml that cannot be read as having no `utilz_version`, and prints "all properly configured" just before item 2's `[6/7]` names it. That is a silent pass, 0053's sibling rather than its class, and each caller reads empty its own way, so it would be an issue of its own.
- `run_doctor` reads `dependencies:` written as a string, a map or a number as a list of that length (`"jq"` counts 2), and checks entries with empty names. It is a wrong answer, not an exit.
- `emacs_doctor` and `emit_integration_tsv` walk the yamls separately, with different rules, though `:1375` calls the latter the single walker. Item 4 brings their rules for `flags` together, not their walks.
