## What

`run_doctor` (`opt/utilz/lib/common.sh:1343-1950` at main `e6628042`) is one function that holds every doctor check inline: UTILZ_HOME, which tree this is, the directory structure, `bin/utilz`, the PATH configuration, the installed utilities, the external dependencies (with the platform notes, the crate probe and menuz's build tools), install integrity, and the summary. Each check's file and tool I/O, its decision rules and its output are all written in the coordinator.

## Design

The constraints, from hv's ruling through vc, bind:

- **Each check is a function of its own, and `run_doctor` only coordinates**: it prints the version line, runs the checks in today's order, totals their issues, and prints the summary and the exit.
- **A check never reports its count through its exit status.** Under `set -euo pipefail` a non-zero return from a bare call ends doctor, and a status stops at 255. A check adds to the coordinator's count instead (run_doctor's own `issues`, which bash's dynamic scope lets a callee update, or one named global), and it returns non-zero only when it could not run at all. Bash 3.2: no namerefs.
- **PFIC where it pays**: a decision that needs no I/O (which tree this is, whether a manifest is current, which dependencies are missing once their entries are read) sits in a function without I/O, and the reads sit at the check's edge. Do not split further than "each check its own function".
- **Behaviour-preserving**: doctor's report and exit status do not change, line for line, on every fixture the suite drives. The suite, unchanged, is the proof, along with a before-and-after diff of `bin/utilz doctor` on the dev tree, which may differ only in the version line's sha.
- **0110 lands on top**: its three silent exits are fixed in the extracted functions, with their own red and green.

cc's design, for vc's read before any code (26 Oct):

- **One function per section of today's report**, in common.sh's DOCTOR COMMAND section beside `_doctor_dep_note`. Each holds its section as it stands, from its `Checking ...` title through its reads, decisions and lines to its closing blank line: `_doctor_check_utilz_home`, `_doctor_check_tree`, `_doctor_check_dirs` (the directory structure), `_doctor_check_dispatcher` (`bin/utilz`), `_doctor_check_path` (PATH, with the link set's health, which prints under PATH's title and counts its own issue), `_doctor_check_utilities` (the installed utilities), `_doctor_check_dependencies` (the yq walk and its notes, exiftool, the crate probe, menuz's build tools and the verdict) and `_doctor_check_integrity` (install integrity with CI's recorded verdict, and the blank line before its title, which it prints today).
- **`run_doctor` coordinates**: the title, the rule and the version line; `have_yq`, resolved once as today; each check called bare, in today's order; then the summary and the exit status, as today.
- **The checks share `run_doctor`'s locals `issues`, `have_yq` and `elsewhere_names`, and nothing else**, each named in one comment where they are declared. Every check adds to `issues` with the line it has today, `issues=$((issues + 1))`; the utilities and dependencies checks read `have_yq`; the utilities check fills `elsewhere_names` for the dependencies check to skip what runs elsewhere (issue 0083). Bash's dynamic scope carries them, in 3.2 as in 5, with no nameref and no new global. `elsewhere_names=" "` moves from the utilities section's `local` line to `run_doctor`'s.
- **No count through an exit status**: each check ends `return 0`, and none has a could-not-run case, since every fault it meets today is a line and an issue. A command that fails inside a check still ends doctor under `bin/utilz`'s errexit, as it does inline today; 0110 fixes the ones that do.
- **Every other variable keeps its scope**: each check declares local what its section declares today, and the dependencies check also declares `name`, which `run_doctor` declares once, in the utilities section, and the dependency walk reuses. The names today's code never declares (`dir`, `util`, `dep_info`) stay undeclared: declaring them changes nothing doctor prints, and it is not this change.
- **`install.sh` is sourced where it is today**, in the PATH check (the link set's health) and the integrity check. It declares nothing at its top level, so sourcing it inside a check scopes nothing differently.
- **PFIC: nothing new is split, because nowhere pays.** The I/O-free decisions are functions of their own already, outside `run_doctor`, and each check keeps calling them. Which tree this is is `utilz_tree`'s answer, which the version line, install's target check, prez's shim and menuz also ask; the check maps it to a line, and reads git only in the dev arm. Whether a manifest is current is `install_manifest_check`'s status; the check maps it to a line, and asks `utilz_tree` only for the old-form status or a tree with no manifest. Which dependencies are missing is `dependency_present`'s answer, entry by entry, in a walk that stops early: an entry's `install` and `required` are read only once it is missing. Reading at the check's edge would run reads that do not run today, and 0110 shows that such a read can end doctor, so the report would change on a fixture where today it does not.
- **Comments**: each section's comments go with it, and its `# Check:` line becomes the function's header. `each_utility`'s list of its consumers (common.sh, "run_doctor twice") names the utilities and dependencies checks instead.
- **The proof, in the one heavy after 0109's run**: the whole utilz suite green, unchanged, on 0111 and on 0111 plus 0110; `bin/utilz doctor` on the dev tree at 0109's commit and at 0111's, diffed, differing only in the version line's sha, with the same exit status; and the same before-and-after diff of the whole report and exit status on doctor fixtures built as tree.bats builds them (a current opt install, an old keg, a manifestless keg under brew's opt link, a dev tree git cannot read, a tree Utilz cannot name), which the suite drives but asserts only in part.
- **0110 on top**, in `_doctor_check_dependencies`, as its body says: red on the 0111 commit, green with the fix.
