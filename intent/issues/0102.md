## What

hv, 22 Oct 2026, in utilz-ic's session, asked whether menuz's log window should colour the three lines it leaves plain (vc's decision 52, point 3, and 0072's point 19): "Yes".

0072 gave menuz its own log window. It shows in red a run that failed, a refusal, and a form or an `open` that failed; in orange a run cancelled or a notice not posted; and in blue each run's start and exit 0. Three kinds of line the app writes still show plain, like the lines that say all is well, though each says that something did not happen:

1. A realise's notes at a menu open (`Realiser.swift:33` to `:52`). Its shell passed the `realise` cap, could not start, or exited before it answered; or a label, an `each`, or an `each` item's label failed to realise.
2. What the top row, arca_swift's `MastheadRow`, logs through the `log` menuz gives it (`MenuzApp.swift:128`, `Masthead.swift:25`). They carry nothing of menuz's own: a refusal opens with its file's path, as in arca_swift's own test of one, `/home/ada/.config/menuz/masthead.yaml: icon = 'logo': is not app or none`.
3. `could not register as a login item: <why>` (`MenuzApp.swift:197`).

## Fix

1. Each of the three shows in the colour 0072's scheme gives what it says: red for something asked for that did not happen, orange for something worth seeing that is not a failure.
2. A realise that passed its cap is orange, as a run cancelled is: its shell was slow, and the menu keeps its last values. A realise whose shell could not start or exited before it answered is red, as a run that failed is, and so is a label, an `each` or an `each` item's label that failed to realise.
3. Every line the top row logs is red, as a refusal of the menu file is: each is a refusal of a file the user can edit, or the About page or a link that did not open. In the log each opens with `masthead: `, the help's word for the row and its window (`help/menuz.md:266`), so the window knows these lines without reading arca_swift's text.
4. `could not register as a login item: …` is orange, as a notice not posted is: menuz runs, and only its start at login is missing.
5. The lines that say all is well stay plain: `registered as a login item`, the lines for a copy that is not the installed one and for a login item left as it is, and the top row's icon note.

1. **Makers in MenuzKit, the bytes unchanged.** Each line gets a maker beside the classifier that reads it, and the app calls the maker, as 0072's point 17 did for the app's failure lines. Each maker writes the bytes of the literal it replaces.
   - `Realise` (MenuzKit's `Realise.swift`, the realiser's pure half) takes the six notes from `Realiser.swift`, and `kept(_:)` with them: `capPassedLine(seconds:kept:)`, `shellNotStartedLine(why:kept:)`, `shellExitedLine(code:kept:)`, `labelFailedLine(id:why:)`, `eachFailedLine(id:why:)` and `eachLabelFailedLine(id:line:why:)`. `Realiser.realise` calls them, so `menuz render`'s `Menuz: ` lines (`Arms.swift:53`) read as before.
   - `LogLine.couldNotRegisterLine(_:)` writes `could not register as a login item: <why>`, and `MenuzApp.registerLoginItem` calls it.
2. **The top row's prefix.** `LogLine.mastheadLine(_:)` writes `masthead: <line>`. `MenuzMasthead.row`, the one function that makes a row, gives `MastheadRow` a `log` that passes each line through it. So the app's log and `menuz render`'s standard error (`Arms.swift:59`) both say `masthead: `, and the icon's note, which goes to `note`, does not.
3. **The classifier.** `LogLine.kind` reads these after the run-id branches, so a run's own output is never taken for one of them:
   - as failure: `masthead: …`, `realise could not start the login shell: …`, `realise's shell exited …`, `label <id> failed to realise (…`, `each <id> failed (…` and `each <id>: the label for … failed to realise (…`;
   - as attention: `realise passed its …` and `could not register as a login item: …`.

   `Kind`'s doc comments name them. LogWindow's switch does not change.
4. **Tests.**

It pins that what the row logs opens with `masthead: ` and reads as failure: arca_swift's real refusal, through the one place that wraps it.
