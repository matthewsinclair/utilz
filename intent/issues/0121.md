## What

Found by kovacs-sysadm testing 2.14.4 on kovacs, a brew-only sleeve, at hv's ask; vc read both in the code. Line numbers are at `60171d27`.

- **`utilz use opt` with no prefix** (`opt/utilz/lib/install.sh:52` to `:56`, `install_prefix_configured`) says "It names where 'utilz install' publishes this checkout, and Molt's sleeve config sets it in every shell." On a brew-only sleeve the prefix is rightly unset, and from a keg there is no checkout, so both claims mislead. The same refusal serves `utilz install` (`:836`) and `utilz use opt` (`:1430`), and its "--prefix DIR names one for a single run" is true only of `install`, since `use` takes no `--prefix`.
- **`utilz use brew` when no Utilz link stands** (`_install_remove_links`, `:1390` to `:1417`) prints "use: removing the Utilz links in <bindir>" before it knows there are any, then "0 removed, 1 left alone (not Utilz links)". The 1 was `~/.local/bin/claude`, which has nothing to do with Utilz.

## Why the census carries a non-Utilz name

`install_link_census` (`:1152`) is the one link-walk that `use`, its report and doctor share (IN-AG-HIGHLANDER-001). It lists every symlink in the link directory with its state, because ownership is decided by where a link points, not by its name. A link named for a utility the tree no longer carries, or a dead link into a tree that has gone, is still Utilz's, and only a walk of every link finds it. So the census is right to carry `claude`, with the state `other`.

The fault is in how `use brew`'s removal reports it. `_install_remove_links` counts every `other` row as "left alone", so it tallies every other tool's link in the directory. `use dev|opt` does not have this fault: its "left alone" counts only names in the link set that a foreign file holds, and Utilz links the tree lacks, each named on a "skipped:" line (`_install_point_links`, `:1316` to `:1376`).

## Design

- **The prefix refusal** says what the prefix is and how to name one. It holds for both callers and makes no claim about a sleeve or a checkout:

  ```text
  UTILZ_INSTALL_PREFIX is not set, so there is no opt prefix
    It names the directory of the opt install: 'utilz install' publishes a
    dev checkout there, and 'utilz use opt' points the links at it. Set it to
    name one, or pass --prefix DIR to 'utilz install' for a single publish.
    There is no default.
  ```

  The test at `opt/utilz/test/install_lib.bats:165` changes with it. It asserts the refusal by name, "Set it to name one" and "--prefix DIR", and refutes "sleeve". In its name, "saying who sets it" becomes "saying what it is and how to name one".

- **`use brew` with no Utilz link** removes nothing and says so. `_install_remove_links` reads the census's Utilz rows first. With none, it prints one success line, "no Utilz link in <bindir>, so Homebrew's install already answers", with no "removing" header and no tally. That claim is checked before it is made: `_install_use_brew` has already asked whether Homebrew's utilz answers on PATH as it stands (its `utilz none` row), and refused if it does not. The version line follows, as now.
- **`use brew` with Utilz links** keeps its header and its "removed:" lines. Its last line drops the tally of other tools' links and reads "<n> removed", with n counted at the run.
- **Tests:**
  - A new row in `opt/utilz/test/use.bats`: a link directory holding only a stranger's link. It asserts success, the no-op line whole, no "removing" and no "left alone", the stranger's link unchanged, and the version line.
  - The row at `use.bats:297` also refutes "left alone".
