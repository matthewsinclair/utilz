## What

hv, 18 Oct 2026, on Gtools' issue to open its console's output in macOS's Console: "based on CC's console research, the move to macOS Console may not be a good idea. If that is the case (and it's ok) then so be it). We should do the reverse, which is have Menuz use the gtools built-in console capablities."

menuz's Log opens the run log in Console.app, which shows none of a run's structure: no colour for a failed run, and no telling one run's lines from another's at a glance.

## Measured

18 Oct 2026, at `2f46784`.

- **menuz's side.** Log is `open` of `${XDG_STATE_HOME:-~/.local/state}/menuz/menuz.log` (`native/macos/Menuz/Menuz/MenuzApp.swift:252`). That is the default app for a `.log` file, Console.app. The log is one file, and every line is ISO-stamped by the app. Its lines are `run <id> start …`, `run <id> exit <code> in <s>`, `[<id>] <output>`, the refusals, the notification lines and the quit line.
- **Gtools.app's console**, measured in Gtools on 18 Oct. About 600 lines of Swift: a window controller (276 lines), a runner (161), a line model with its level classifier and a bounded ring (60), and the streaming part of its CLI shell (about 107), with tests. It tails a child process through a pipe and colours each line by level.
- **The tail.** `tail -F` keeps following a file that is truncated in place, which is how Gtools' own logs rotate.

3. **What menuz's adoption needs from it:**

## Design

utilz-ic, 19 Oct 2026. Drafted against ArcaLogConsole as gtools-ic's WP-09 stands at `27ff5fe` in `~/Devel/scratch/gtools-ic/wt-wp09`, before arca_swift 0.2.0 is tagged. Size: M. Point 9 says what to read again once it tags.

1. **What ArcaLogConsole gives menuz** (`Sources/ArcaLogConsole/LogConsole.swift`):
   - `LogConsole(title:capacity:theme:)`, on the main actor;
   - `follow(file:as:classify:backlog:)`, which follows a file in-process across a truncation or a rename, and waits silently for one that is not there yet (`FileFollower.swift:1` to `:30`);
   - `showWindow()`, which makes the window on first use and brings it forward;
   - a `ConsoleClassifier`, `(String) -> ConsoleLine.Kind`, with the kinds log, error, warning, marker and quiet; `ConsoleClassify.unstamped` skips one leading RFC 3339 stamp, which every app line of menuz.log opens with.

   Fix item 3 needs three things, and it covers all three: the file source that keeps following, menuz's own classifier, and no runs from the console. menuz never calls `run` or `follow(command:)`.
2. **One classifier, beside the lines it reads.** `MenuzKit`'s `Run.swift` and `Notice.swift` make menuz.log's lines (`Run.startLine`, `cancelledLine`, `quitLine`, `notRunLine`; `Notice.launchLine`). A new `LogLine.kind(_:)` in MenuzKit reads them, after the stamp, as MenuzKit's own `LogLine.Kind`: failure, attention, frame, output, quiet or plain. That way MenuzKit takes no GUI library. The app maps each kind to a `ConsoleLine.Kind` in one switch:
   - `run <id> start "<label>" …` is frame, shown as a marker;
   - `run <id> exit 0 in <s>` is frame, a marker;
   - `run <id> exit <n> in <s>` with n not 0 is failure, an error, which shows red;
   - `run <id> cancelled "<label>"` is attention, a warning;
   - `run <id> could not start: …`, `"<label>" not run: …`, `refused: …`, `"<label>" form: … could not be read: …` and `open … did not succeed: …` are failure, errors;
   - `[<id>] notice not posted: …` is attention, a warning, and `[<id>] notice posted` is quiet;
   - any other `[<id>] …` is output, plain;
   - every other line is plain: the quit line, `notifications: granted`, login-item lines and the top row's note.

   Fix item 3 asks that a refusal show red, start and exit lines be accented, and `[<id>]` output be plain; this is that.
3. **Log opens the console.** `MenuzApp.openLog` (`MenuzApp.swift:276`), reached from the Log item and from a `menuz: log` entry, calls a small `LogWindow` in `Menuz/Services` instead of `open`. `LogWindow` owns one `LogConsole` titled `menuz log`. It follows `paths.logFile` with a backlog of 200 lines the first time it is shown, follows again when the file it follows is no longer `paths.logFile` (a reload can move the state folder, `MenuzApp.swift:111`), and then calls `showWindow()`. Nothing is followed before the first open, so a menuz that never shows its log reads nothing.
4. **What does not change.** The Log item stays disabled, as "Log (no log yet)", until the log exists (`MenuBuilder.swift:94`). The `menuz log` command still tails the file in a terminal. menuz's runs still write the file themselves, detached (D9).
5. **The pin.** `project.yml`'s `ArcaSwift` goes from `minorVersion: 0.1.1` to `minorVersion: 0.2.0`, on purpose, as its comment asks (`project.yml:21`). The Menuz target gains the `ArcaLogConsole` product beside `ArcaMasthead`. The pins file is `Menuz.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` (0073's amendment, cd965bb), re-resolved to 0.2.0's revision and checked by its SHA. arca_swift's tools version stays 6.2, and the menuz app job already runs on macos-26 (`tests.yml:522`), so the toolchain floor is unchanged.
6. **The tests, red first.**
   - MenuzKitTests' `LogLineTests` builds each line through MenuzKit's own makers (`Run.startLine`, `cancelledLine`, `quitLine`, `notRunLine`, `Notice.launchLine`) and stamps it as `AppLog` does, then pins its kind. A format changed in one place therefore fails there. Exit 0 and exit 2, `[<id>]` output that itself contains `exit 2`, a line with no stamp, and an unknown line are covered too.
   - MenuzTests' `LogWindowTests` pins that the first show follows `paths.logFile`, that a second show of the same file follows nothing new, and that a show after the path moved follows the new path. It does this through a recording seam for the follow, so no window or file watch is made under the test host.

7. **Docs, version and CHANGELOG.** `help/menuz.md`'s Log item says it opens menuz's own log window, which follows the log, colours a failed run red, accents each run's start and exit, and finds with ⌘F, in place of Console.app. One CHANGELOG line goes under Changed. menuz moves by a patch number: which one is set at the landing, after 0083's 0.4.3.
