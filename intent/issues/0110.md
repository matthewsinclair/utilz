## What

`utilz doctor` runs under the dispatcher's `set -euo pipefail` (`bin/utilz:9`), and `run_doctor` is called bare (`bin/utilz:118`), so errexit is live inside it and inside each check it calls. Three reads in `_doctor_check_dependencies`, which issue 0111 moved out of `run_doctor` unchanged, have no handler. One that fails ends doctor mid-report, before its summary, and each read's `2>/dev/null` throws away the reason. Line numbers are at 0111's commit `8c9921b5`, in wt-0109:

- the dependency loop's `install` read, `dep_install=$(yq eval ".${dep_list}[$i].install" "$yaml_file" 2>/dev/null)` (`opt/utilz/lib/common.sh:1739`);
- its `required` read, `dep_required=$(yq eval ".dependencies[$i].required" "$yaml_file" 2>/dev/null)` (`:1742`);
- the crate probe, `crate_count=$(find "$UTILZ_HOME/opt" -mindepth 3 -maxdepth 3 -path ... 2>/dev/null | wc -l | tr -d ' ')` (`:1807`). This is a probe ending in a pipeline under pipefail, the class of 0053 that 0080 swept: if find meets an unreadable directory under `opt/`, the assignment fails.

The same loop's other reads were hardened against exactly this: the entry's name (issue 0085, `if ! dep_name=$(yq ...)`) and its platforms (issue 0083, `dep_where=$(...) || dep_where_status=$?`). These three are the ones that sweep missed.

vc's critic leg on 0109 v2, 26 Oct 2026 (critic-shell, rule IN-SH-CODE-005; the agnostic rule is No Silent Errors), then verified by vc's own read. 0109 does not cause it and does not touch these lines.

## Design

- **Each yq read gets the loop's own handler.** A read that fails is refused by name, as the platforms read is, with `yaml_read_error`'s reason: `<name>: <list>[<i>] (<dep>): its install line cannot be read: <reason>`, and `<name>: dependencies[<i>] (<dep>): whether it is required cannot be read: <reason>`. It counts an issue and a refused entry, and the sweep goes on with `continue`, so the verdict says an entry was not checked, as it does for the loop's other refusals. A `required` value that cannot be read is never taken as required or as optional.
- **The crate probe says when it could not count.** find's stderr is kept with its stdout, and its status is taken. The count is the lines that name a crate's `Cargo.toml`, so a stray line on stderr is never counted as a crate. If find fails, doctor warns, `The crates under <root>/opt cannot be counted, so whether Rust is needed is not checked: <find's errors>`, counts an issue, leaves out the Rust note, and goes on to its summary. A probe that failed never reads as zero crates.
- **Where every read succeeds, doctor prints what it prints today**, so 0111's before-and-after diffs on the dev tree and its fixtures hold at 0111 plus 0110 too.
- **Tests, red on 0111's commit and green with the fix**, in common_lib.bats beside the sweep's tests for 0080 and 0085. Each runs doctor under `set -euo pipefail`, as `bin/utilz` does (`run_common_strict`), on a fake home whose run before the fault gives the count the fault adds one to. The first two put a yq first on PATH that fails on one field of a dependency entry and hands every other read to the real yq: the `install` field, then the `required` field, of a missing dependency that beta declares. The third gives the home's `opt/` a directory of mode 000, and is skipped where the user can read it anyway, as root can, as the 0081 tests are. Red: doctor stops early with no summary, and nothing says why. Green: the refusal or the warning is named, the summary prints and the issue count is one more; the missing dependency is reported neither as missing nor as optional.
