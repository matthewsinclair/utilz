The prez crate has been unformatted since 504825a and CI is the first thing that noticed, one push later.

MEASURED. `cargo fmt --all --check` reports six diffs in four files:

- `crates/showreel/src/config.rs:322`
- `crates/showreel/src/record.rs:197`
- `crates/showreel/src/video.rs:16`, `:499`, `:514`
- `crates/showreel/src/zone.rs:57`

The same six, byte for byte, on CI and on this machine.

WHERE IT ENTERED. A worktree bisect over every commit touching `opt/prez/crate` since 143198d (the commit that adopted rustfmt) reads CLEAN for all fifteen commits up to and including e079c08, and DIRTY 6 from 504825a onward. So 504825a introduced all six, and 75b3796, 30c63e3, 5fd3cca and 7632d2f each carried them forward unchanged.

WHAT IT BLOCKS. `bin/devbin check all` is a release gate and it fails on `format`, so the cut refuses at the gates step until this is fixed. CI run 35715724687 on 7632d2f is red for this and this alone: `Rust Lint (clippy)` failed in 11s at its "Check formatting and run clippy" step, which runs `cargo fmt --all --check` BEFORE clippy precisely so drift fails the step before anything compiles. Clippy itself never ran, so its verdict on this tree is still unknown.

THE CAUSE, AND WHY FOUR COMMITS GOT THROUGH. Nothing between a Rust edit and a push checks formatting. `bin/devbin check all` catches it and is not run per commit; `utilz test prez` and ST0024's 13/13 acceptance run do not check formatting at all, so cc's green was true and did not cover this. The repository's `.git/hooks/pre-commit` has a formatter-refuses stanza, and it covers markdown only -- its closing comment reads "Utilz is bash-only, has no mix.exs", which stopped being true when the prez crate landed and `rust` joined `shell` in `intent/.config/config.json` languages. That hook is untracked, so the gap is local to a machine rather than shippable; it is filed separately.

THE FIX. `bin/devbin fmt rust`, which is the project's declared write-mode arm (`cargo fmt --all --manifest-path opt/prez/crate/Cargo.toml`) and the exact counterpart of the `check format` command line that failed. rustfmt reformats and changes no behaviour; the crate's suites are re-run after it to show that.
