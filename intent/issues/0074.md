## What

menuz refuses a menu file that is not YAML with only the first line of Yams' error (`native/macos/Menuz/MenuzKit/Sources/MenuzKit/MenuLoader.swift:34`). When the error carries a context, the context fills that first line and the problem is on the second, so the refusal says where libyaml was reading and drops what it found wrong.

gtools-ic found the same cut in ArcaCore during arca_swift's review, and noted that menuz has it too. vc routed it to utilz-ic to file and fix, and hv said "Do them now" in utilz-ic's session (18 Oct 2026).

## Measured

18 Oct 2026, on the installed Menuz.app (0.3.0, build 1242, `56e0c90d`), in a run booked with gtools-vc. The menu file is two lines, and the second has lost its colon:

```yaml
notify: failure
menu
```

`Menuz --validate <file>` exits 2 and prints one line:

```text
<file>: not YAML: 3:1: error: scanner: while scanning a simple key in line 2, column 1
```

The problem, `could not find expected ':'`, is not in it.

In Yams 6.2.2, the version MenuzKit resolves, the scanner, parser and composer errors each print `<mark>: error: <kind>: <context><problem>:` and then a snippet of the file, and `YamlError.Context.description` ends in a newline (`YamlError.swift:98`, and `:181` to `:185`). So a context always moves the problem onto the line the cut drops. Without a context the problem stays on the first line, which then ends in a stray colon. The reader and duplicate-key errors keep their problem on the first line, so the note at `MenuLoader.swift:348` to `:350`, that a key given twice is refused naming the key, still holds.

## Fix

After 0073 lands, in its own commit, through the same gate as 0073: runs booked with gtools-vc, vc's read of the bytes, and hv's word.

1. **One line, from YamlError's fields.** For the scanner, parser and composer errors, the refusal is built from the error's mark, kind, context and problem, never cut from its text. The two-line file above then reads:

   ```text
   <file>: not YAML: 3:1: error: scanner: while scanning a simple key in line 2, column 1: could not find expected ':'
   ```

   An error without a context reads as it does now, less the stray colon. Every other error keeps its first line.

2. **A test pins both forms** in `ValidatorTests.swift`, beside the not-YAML tests at `:357` to `:370`: the two-line file above, and an error without a context.
3. **The CHANGELOG** says the refusal now names the problem. `help/menuz.md:200`, which gives the refusal's shape as `<file>: <why>`, is unchanged. menuz's version number is hv's, asked for with the landing.
