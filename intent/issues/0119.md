## Method

**The criterion is 0113's** (`intent issues show 0113`, "The criterion"), so this issue and 0113 judge alike. A number goes when it counts the members of something that can grow, or names a member by its position. It stays when it is an identifier, a format or contract value (exit status, size, timeout, field width), the input a test builds, or the output it asserts of its own construction.

The ledger's keep classes, read for code:

- exit status;
- emptiness, absence or uniqueness (`-gt 0`, `-eq 0`, exactly once);
- the test's own construction (calls, files or rows it made itself), and a fixture's values;
- a format or contract value (a column format, Apple's AppIcon slots, a protocol constant);
- a threshold (bytes, pixels, polls, seconds);
- an arity or a budget;
- an identifier or a version;
- a diagnostic excerpt (`head -1` of an error file in a failure message).

The delete classes:

- a floor or a total on the tree's members;
- a count of a utility's own rows, stamps, credentials or calls, which its own lists fix;
- the size of a test's own case table, which is a number of checks, or of a production roster;
- checks ran;
- a count or a position in a user-facing string.

**The population, by command at a named commit.** `population.sh <commit>` (banked, below) takes every file `git ls-tree -r <commit>` lists. It puts each one in exactly one of test code, production code, or excluded with its reason; the first matching rule wins. It names each file's language from its extension or shebang. A file whose language no rule names prints as unknown, and the scan refuses it; at `4ae253fe` it prints none. The scan's base is the first main commit after 0117 lands, and the ledger records it.

**The cut, shared with 0113.** Each file is cut once into code, strings and comments, with positions, by a single tool. 0113's extraction already specifies it: shfmt's parser for shell and bats, its lexers for Rust, Swift and Lua, and prettier's parsers for JS and HTML. It proves its own cut: the pieces join back to the file byte for byte. 0113's detection reads the comments and names; this issue's reads the code and the strings. Every number in the population then belongs to exactly one owner:

- a comment or test name (0113);
- the dispatch suites (0117);
- code or a string (this issue);
- an excluded file.

The run prints each number's owner, and refuses a number with no owner or with more than one. The cut does not cover elisp, Ruby, Python, YAML, CSS, JSON or the Xcode configs, so those files are read by hand and named in the ledger with what they hold.

**Detection.**

- **In test code**, every numeral in:
  - a test expression or an arithmetic comparison (`[ ]`, `[[ ]]`, `(( ))`, `test`);
  - an argument to the BATS helper's `assert_*` and `refute_*`, or to `fail`;
  - a Rust `assert!`, `assert_eq!` or `assert_ne!`; a Swift `#expect`, `#require` or `XCTAssert*`; a Lua `check` or `assert`; a JS `check` or comparison;
  - a subscript (`${lines[N]}`, `[N]`, `.nth(N)`);
  - a position argument (`head -n`, `tail -n`, `sed -n 'Np'`, `NR==`, `cut -f`).
- **In strings**, in test or production code: numerals as whole tokens, the number words on 0113's list, and ordinals if vc answers 0113's question on positions yes.
- **In production code**, every string: shell words and heredoc bodies; Rust, Swift, Lua, JS, elisp, Ruby and Python string literals, except those in a Rust test item; YAML scalars; and the text in the shipped HTML, JS and CSS.

**The ledger.**

- **Rows:** one per hit. Each row gives the file, the line, the line's text, the number, its context (assertion, subscript, position or string), the verdict (delete or keep) and its class. A delete row also gives the replacement and the mutation that proves it.
- **Classes put by rule:** mechanical classes are put by a named rule, and every row is still listed. Examples: an exit status read from `$status`, `$?` or `rc`; `-gt 0` and `-eq 0`; a diagnostic `head -1`.
- **Matching:** rows match by file and text, since line numbers move.
- **Banking and reads:** banked outside the tree with sha256s and never committed. ic reads the Menuz rows first; then vc reads the ledger before any edit, and again with the diff.
