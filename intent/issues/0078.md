## What

hv, 19 Oct 2026: with 0071's two lines in `~/.config/menuz/menuz.yaml` (Desks…'s `checked: "$(arngz current || true)"` and Discover…'s `default: "$(arngz current || echo today)"`), the menu ticks nothing and the form offers `today`, although `arngz current` prints `zeopit`.

menuz puts its own `bin/` first on PATH for a run and for a realise (`native/macos/Menuz/MenuzKit/Sources/MenuzKit/Paths.swift:29`), and hv's `~/.config/menuz/bin/arngz` points at the source tree's arngz 1.1.0. A run exports it inside its shell, after the login files have run (`MenuzKit/Sources/MenuzKit/Run.swift:109`). The realiser only sets it in the environment it starts `zsh -ilc` with (`native/macos/Menuz/Menuz/Services/Realiser.swift:22`), and the login files then rebuild PATH with `/opt/homebrew/bin` ahead of it. So labels, eaches, `checked:` and form defaults (`MenuzApp.swift:243`) run `/opt/homebrew/bin/arngz`, the 2.14.0 keg's arngz 1.0.1, which has no `current`, while runs run the menu's own. The fallbacks then read "cannot answer" as "no desk recorded". `Realiser.swift`'s own comment says the realise gets `bin/` first "as for a run".

## Measured

19 Oct 2026, at `4611b1c`, on hv's machine:

- `PATH="$HOME/.config/menuz/bin:$PATH" zsh -ilc 'command -v arngz'` prints `/opt/homebrew/bin/arngz`, and `$(arngz current || true)` there is empty.
- `zsh -ilc 'export PATH="$HOME/.config/menuz/bin:$PATH"; command -v arngz'` prints `/Users/matts/.config/menuz/bin/arngz`, and `$(arngz current || true)` there is `zeopit`.
- `Menuz --render ~/.config/menuz/menuz.yaml`, on the installed 0.3.0 (build 1242), lists Desks… as `rhad` and `zeopit` with no tick.
- hv's Discover… runs 24, 26 and 27 (05:05Z to 05:09Z) wrote arngz's record, so they ran 1.1.0 from the menu's `bin/`.

## Fix

1. The realise shell puts the menu's `bin/` first after the login files, as a run does, and both take the line that does it from one place.
2. A test pins it: a realise whose login PATH has a same-named command ahead of the menu's `bin/` runs the menu's.
3. The CHANGELOG under `[2.14.1] - unreleased`.

Owner utilz-ic, routed by vc on hv's word that everything outstanding ships in 2.14.1 (19 Oct 2026), through the same gate as 0073.

## Design

utilz-ic, 19 Oct 2026, with each file:line re-read at main's head `23d7575`, where menuz's files are as they were at `9ae4576`. Size: XS.

1. **One line, in one place.** A new `Paths.binFirst` in `MenuzKit/Sources/MenuzKit/Paths.swift`, beside `runPath` (`:29` to `:33`), holds the shell line `export PATH="$MENUZ_HOME/bin:$PATH"`. Its comment says what it is for: run inside a login shell once the login files have run, it puts the menu's `bin/` back in front of whatever they put first. `runPath` stays as it is, the PATH the shell starts with. The line holds no path and no menu text: it reads `MENUZ_HOME`, which both callers already set (`Run.swift:59`, `Realiser.swift:23`).
2. **The run takes the line from there, unchanged.** The wrapper (`Run.swift:94`) writes the line out at `:109` today. It interpolates `Paths.binFirst` there instead, so the wrapper's text is the same, byte for byte.
3. **The realise gains it.** Realise's script (`MenuzKit/Sources/MenuzKit/Realise.swift:175`) opens with the line, so everything it runs comes after it: the menu's labels, `each` lines and `checked:` (`MenuzApp.swift:205`), a form's `choices:` and `default:` (`:236` to `:245`, through `formAnswer` at `:318`), and `--render` (`Arms.swift:51`). All three reach the shell through `Realiser.realise`, whose starting environment (`Realiser.swift:20` to `:23`) does not change. Its comment (`:4` to `:7`) says `bin/` is first after the login files, as for a run.
4. **What does not change:** the login shell's capture (`LoginShell.swift:21`), which keeps PATH as the login files leave it, since menuz's paths and validation's exported names are read from it; and the shim, which neither runs nor realises.
5. **The test, red first.** A new `MenuzTests/RealiserTests.swift`, in the app's test bundle because `Realiser` is the app's. It gives a fixture `HOME` and `ZDOTDIR`, so none of the user's startup files takes part, whose `.zprofile` puts a fixture directory first on PATH, as Homebrew's `shellenv` puts `/opt/homebrew/bin` there. That directory holds a `menuz-probe` that prints `login`, and the menu's `bin/`, under a fixture `MENUZ_HOME`, holds a `menuz-probe` that prints `menu`. `Realiser.realise` of a label `$(menuz-probe)` and of an `each` whose line is `menuz-probe` must answer `menu` for both. On main both answer `login`. The run's side stays pinned by `WrapperTests.swift:134`. The regenerated project file takes the new test file.
6. **Docs.** `help/menuz.md:50` already says `bin/` "is first on `PATH` for every run and every realised label", which this makes true, so the help does not change. The CHANGELOG gains a Fixed entry under `[2.14.1] - unreleased`.
7. **Runs,** each booked with gtools-vc: `utilz menuz test` with the new test and without the fix, where only the new test fails, then with the fix, where all pass. The shim does not change, so no shell suite runs before the landing, which runs `install_e2e.bats` in the primary as 0069 to 0071 did.
