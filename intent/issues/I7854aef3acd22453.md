## What is wrong

The macOS job of the tests workflow fails 28 of its 274 tests. Each fails with `run_devbin: no bash at devbin's floor (5 or later) on this machine`. Dispatch 45954594945 on e1d10b06 (27 Nov 2026) shows it.

`devbin_bash` in `opt/utilz/test/test_helper.bash` finds the bash 5 that `run_devbin` runs devbin under. It looks in `$HOMEBREW_PREFIX/bin`, `/opt/homebrew/bin`, `/usr/local/bin` and the PATH. The macOS job installs Homebrew's bash and unlinks it, so that `/usr/bin/env bash` still finds `/bin/bash` 3.2 for the other suites (issue 0130). The job gives that bash 5 to the tests as `UTILZ_TEST_BASH5`. `devbin_bash` does not read `UTILZ_TEST_BASH5`, so on the runner it finds no bash 5.

On a Mac where Homebrew's bash is linked, `devbin_bash` finds `/opt/homebrew/bin/bash`, so a local run does not show the fault. The fault came in with 2c9f7d99 (issue I59c806c), which added `devbin_bash`. The last green macOS dispatch, on b4673003, came before that commit.

## Fix

`devbin_bash` tries `${UTILZ_TEST_BASH5:-}` first, then the places that it reads now. Each candidate must still be bash 5 or later. menuz's `macos.bats` already reads `UTILZ_TEST_BASH5` first in the same way.

## Proof

Static checks only: `bash -n` under bash 3.2 and 5, and shellcheck with no new finding. The proof is the next macOS dispatch of tests.yml, after hv's push: the 28 tests pass there. There is no local run, because a Mac with a linked bash 5 passes with and without the fix (no test of a test).
