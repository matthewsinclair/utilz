## Summary

`utilz doctor` reads a utility's dependencies from its yaml in check 6 (`run_doctor`, `opt/utilz/lib/common.sh`), and it honours only the required half.

- **`optional_dependencies` is never read.** utilz.yaml declares glow, bat and bats-core, and mdagg.yaml declares glow, each with a name, an install line and a purpose. A missing one is reported only when a hand-written line happens to name it: glow is named, bat and bats-core are not.
- **`required: false` is read as required.** syncz.yaml lists unison under `dependencies` with `required: false`. A machine without unison is told a dependency is missing, and check 6 counts it as an issue.
- **Hand-written lines repeat declared ones.** glow is hand-written as well as declared twice. rsync is hand-written as well as declared by syncz.yaml, so a missing rsync is reported twice.

ST0021's WP-04 found it. hv's answer 7 declares ffmpeg "as an optional dependency of prez (prez.yaml optional_dependencies), so doctor reports it", and doctor would not.

## Fix

- **Check 6 walks every utility's optional declarations**: its `optional_dependencies`, and any `dependencies` entry marked `required: false`. Each missing one is reported as info, with the yaml's own install line and purpose, so common.sh holds no install line of its own.
- **Info, never a failure.** Doctor's verdict and exit status do not move for a missing optional dependency.
- **One line per name**, naming every utility that declares it.
- **The hand-written glow and rsync lines go**, because the yaml declares both. exiftool, which no yaml declares, and the Rust toolchain check stay.
- **Without yq**, doctor says the optional declarations went unread, rather than skipping them in silence.
- **The report stays on stdout** with the rest of doctor's (hv's decision 1(2)).
- **prez.yaml declares ffmpeg.** The 2.10.0 CHANGELOG entry names the lines a user may now see: bat, bats-core and ffmpeg, and unison as optional rather than missing.

## Resolution

Fixed in the commit that closes this issue: `opt/utilz/lib/common.sh`, with `opt/utilz/utilz.yaml` and five new tests in `opt/utilz/test/common_lib.bats`.

- Check 6 walks every utility's `optional_dependencies`, and every `dependencies` entry marked `required: false`. Each missing one is an info line carrying the yaml's own purpose and install line, once per name, naming every utility that declares it. Doctor's verdict and exit status do not move.
- The hand-written glow and rsync lines are gone. exiftool, which no yaml declares, and the Rust toolchain check stay. Without yq, doctor says the optional declarations went unread.
- Reading the declarations exposed one error in them: utilz.yaml named the command `bats-core`, which is the brew package, so doctor reported bats missing on a machine that had it. It names `bats` now, and installs `bats-core`.
- Checked under bash 3.2.57, with `/bin` first on `PATH`:
  - `common_lib.bats` passes 58 of 58, and `dispatcher`, `integration` and `help_dispatch` pass.
  - Against HEAD's `common.sh`, four of the five new tests fail. The fifth, that an installed tool draws no line, passes there too, as it must.
  - On this machine, doctor's exit status and issue count are unchanged from HEAD's.
  - `shellcheck -x` on `common.sh` is clean.
