## What

Found by utilz-cc while reading for 0107, 25 Oct 2026. mdagg warns "File not found" for a missing file and is meant to carry on, which is what its own test's name says ("error: missing file shows warning but continues"). It stops at the missing file instead: every file after it is lost, and mdagg exits 1.

## Measured

- `process_file` warns and returns 1 for a missing file (`opt/mdagg/mdagg`, at `warn "File not found: $file"`), and mdagg runs under `set -euo pipefail`. So a call that returns 1 ends the script.
- cc ran it on 25 Oct with a.md, missing.md and c.md listed on stdin. mdagg printed a.md, warned, exited 1, and never printed c.md. The same happens without 0107's change.
- The existing test checks only the file before the missing one, so it passes anyway.

## Fix

mdagg warns for each missing file and carries on with the rest, in every input mode. If any file was missing, it exits non-zero at the end, so the failure still surfaces (No Silent Errors) and a caller can still tell that something was left out. The test is rewritten to put a file after the missing one and assert that the later file appears, the warning names the missing one, and the exit code is non-zero. It is proven red on today's code. A CHANGELOG line goes beside 0107's, and mdagg's VERSION goes with 0107's bump.

Size: XS. It goes in the next release under hv's one-next-release ruling (25 Oct).
