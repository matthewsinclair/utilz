## Summary

`install_manifest_write` records the source tree's address in the manifest's `source-tree` row. The comment at `opt/utilz/lib/install.sh:341-343` says the row is "Resolved physically, because a relative or symlinked spelling would name a tree that only resolves from where the publish happened to be run." The code at `:345` resolves it logically, with `cd "$tree" && pwd` and no `-P`. ST0019's install-model survey found it on 2026-09-14.

**The code is right and the comment is wrong.**

- The row is an address, and other code compares it as a string. `install_use_report` compares it with each PATH link's root (`:1273`). `_install_link_root` resolves that root logically (`:1029-1036`), and the dispatcher derives its own home the same way (`bin/utilz:37` and `:40`). `use dev` builds its links from the row's own spelling (`_install_use_tree`, `:1224`), so a logical row and a logical link root agree by construction.
- The comment's reason does not hold. An absolute path through a symlink resolves from anywhere. Only a relative spelling depends on the directory the publish ran from, and `cd "$tree" && pwd` makes it absolute whether or not it resolves symlinks.
- The one physical resolution in the file is right where it is. `_install_is_git_toplevel` (`:79`) compares against `git rev-parse --show-toplevel`, which git reports physically.

**The fallback contradicts the rule as well.** If the `cd` fails, `|| source_tree="$tree"` records the unresolved spelling, relative or not, and says nothing. That is a default standing in for a failed read, the trap `intent/restart.md` records. It cannot fire today: `:314` (`$tree/VERSION`) and `:321` (`git -C "$tree"`) both fail first for any tree `cd` cannot enter. But it states the opposite of the rule the row exists to follow, and it would become reachable if either earlier check moved.

## Fix

- The comment says the row is resolved logically, like the dispatcher's home and every link root it is compared with, and names the one physical exception and why.
- The fallback refuses by name, as the `git -C` failure at `:321` does, instead of recording an unresolved spelling.
- No test is added. A comment is not behaviour, and the refusal cannot be reached (above). The install suites and shellcheck run on the changed file as the check that nothing else moved.
