`tools/test-estate` (issue 0051) re-execs `bin/utilz test` with `/bin` first on PATH so that bats and every suite run under the bash macOS ships. It asserts nothing about what it got.

On this machine `/bin/bash` is 3.2.57 and the mechanism holds -- verified by cc: with `/bin` first, bats, its libexec helpers and `acceptance.sh` all resolve to 3.2.57, so it is the TESTS that run under it and not merely the dispatcher, while `git`, `yq`, `gh`, `cargo` and `shellcheck` still resolve behind it. On any machine where `/bin/bash` is not 3.2 -- a future macOS, a Linux box, a container -- the gate runs the suite under whatever it finds and still reports green. That is precisely the failure 0051 was filed to close: the gate stands between a green tree and a tag, and a gate that cannot tell whether it did its job is a gate that says "we think" where the issue promised "it did".

THE FIX, three lines: read `/bin/bash --version`, and refuse by name when it is not 3.2, saying what it found. A refusal is right rather than a warning, because the whole point of the wrapper is that this is the one run under the shipped bash; if it cannot be, the release gate should say so and stop rather than pass silently.

SECOND, SMALLER, SAME FILE: 0051's evidence cites `tools/test-estate utilz`, one utility. The gate runs it with NO argument, the whole estate, and that configuration is not in the evidence. The cut's own gate run closes it, and until then the claim is one configuration wider than what was measured.
