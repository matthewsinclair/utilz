## What

`opt/prez/crate/crates/artifact/src/theme.rs`'s test helper `dir(name)` (`:1094`) creates `$TMPDIR/artifact-theme-<pid>-<name>` and nothing removes it. Its 9 callers make 9 directories per run of the crate's tests, so every `cargo test --release --workspace` leaves 9 behind: on this Mac, on kovacs and on CI's runners. On 19 Oct 2026, cc found 36 in TMPDIR from four of its own runs (slots 147, 161 twice, and 168) and removed them.

cc found it while removing the leftovers of slot 168's red run, and vc ruled it its own issue: cc's, low, XS, for 2.14.1, after 0089, design first.

## Fix, for the design to settle

The helper removes its directory on every way out, as a guard dropped when the test ends, whether it passes or panics. The test is red by the TMPDIR count: the number of `artifact-theme-<pid>-*` directories left after the theme tests run is 9 on main's code and 0 after. Size: XS.

## Measured

By reading, at `c50b08b`, and by the count of directories each run left, 19 Oct 2026.

## Design

cc, 19 Oct 2026, at `6a9735e` (0089 landed). Size: XS. Read and approved by vc, 19 Oct, which added point 2 and point 6's CHANGELOG line.

1. **The helper returns a guard that removes its directory when dropped.** `dir(name)` (`theme.rs:1094`) returns a small test-only `TempDir(PathBuf)` whose `Drop` runs `std::fs::remove_dir_all` on it. It derefs to `Path`, so the 9 callers (`:1150`, `:1209`, `:1511`, `:1687`, `:1723`, `:1743`, `:1779`, `:1800`, `:1847`) keep `let d = dir("...")` and use `&d` or `d.join(..)` as today. Dropped at the end of each test's scope, it removes the directory whether the test passes or panics, since a panic unwinds through the drop.
2. **No silent error in `Drop`.** A `NotFound` is ignored, since the directory is already gone. Any other error panics with the path and the error, but only when `!std::thread::panicking()`: a panic inside an unwind aborts the test binary and hides the first failure, so a test already failing keeps its own message.
3. **No new dependency.** `tempfile` is not in the workspace, and a ten-line guard in the test module needs none. If another crate's tests want the same, the guard moves to `artifact`'s test support then, not now.
4. **The test, red first, by the TMPDIR count.** One test in `theme.rs` makes a `dir("guard-probe")`, writes a file in it, drops it, and asserts the path is gone. On main's helper, which returns a bare `PathBuf`, the probe's directory survives and the test fails at that assertion. The run also counts `$TMPDIR/artifact-theme-<pid>-*` after `cargo test -p artifact`: 9 on main, 0 after.
5. **Runs.** The crate's tests red on the first build, then green; `bin/devbin check all`; booked heavy with utilz-vc; dc's kovacs leg on Linux, where the count is read in `/var/tmp`'s run dir or `/tmp`. Built on 0089's commit, 6a9735e.
6. **Versions and CHANGELOG.** Only tests change, so prez stays at 0089's 2.5.3. One CHANGELOG line under 2.14.1's Fixed, as 0088's and 0091's test-only fixes have.
