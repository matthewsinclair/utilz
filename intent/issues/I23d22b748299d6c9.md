The header of tools/ci-suites says: "No binary is built here, so its one arm that reads the compiled version skips." On Ubuntu that is false. CI run 45586654771 on df0c8cda ran that arm (opt/prez/test/prez.bats:626), and prez.bats ended 32 ok, 0 skipped.

Cause: the utilz suite runs before prez's. bridge.bats test 18, "every declaring utility ACCEPTS the command form the bridge builds", runs each utility that declares an integration block through the real dispatcher. prez's yaml declares `flags: [build]`, so the test runs `utilz prez build /nonexistent-probe.dat`. prez's shim finds no binary and runs `cargo build --release --workspace` with the runner's cargo. The test captures the build's output, so the job's log shows only its time: 54.5 s before "ok 18". So opt/prez/crate/target/release/prez exists when prez.bats runs.

Fix: cut that sentence, so that the comment predicts nothing that another suite decides. Where no binary is built, prez.bats's skip gives its own reason.

The probe's build stays, by vc's reading of 25 Nov 2026 that it is a cost to keep. In the Ubuntu job it builds prez's whole workspace (54.5 s in this run), and the rust job builds the crate again. The macOS job has not run prez.bats yet: it skips a push to main.
