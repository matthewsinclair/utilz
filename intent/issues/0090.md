## What

Each run of the utilz suite leaves one file in `$TMPDIR`: a 179-byte `tmp.XXXXXXXXXX` holding an empty todo file (`generator: utilz todo`, `next-id: 1`, every bucket `_(none)_`). todo's `write_file` (`opt/todo/todo:331`) writes the new file to `tmp=$(mktemp)` and then `mv "$tmp" "$TODO_FILE"`, and `_prepend_file` (`:478`) does the same, so a `mv` that never runs, or fails, leaves the temp file behind.

Measured by dc on 19 Oct 2026, on `9bb32fa`, under bash 3.2.57 and 5.3.20. Slot 137 left `tmp.tg2uZDiOLL` 27 seconds into the bash 3.2 pass of the utilz suite and `tmp.14RkXyDyTg` 6 seconds into the bash 5 pass. Slot 145 left `tmp.4CcIQLscAh` and `tmp.QL28BhcCi1` at the same points. It is already on main: 0083 does not touch todo or the utilz suite's callers of it. The likeliest caller is `opt/utilz/test/bridge.bats:204`, which runs every utility that declares an integration block, todo among them; that is not yet shown. vc ruled it its own issue (19 Oct 2026), dc's, XS, after 0088.

## Lead, by reading, to confirm in step 1

dc, 19 Oct 2026, after slot 154. 154 ran the whole utilz suite with TMPDIR at a fresh dir of its own, and that dir was left empty, yet the system TMPDIR still got an empty todo file 26 s and 5 s into each pass (16:09:24Z and 16:11:57Z), as in 137 and 145.

- macOS `mktemp` with no template ignores TMPDIR and uses `_CS_DARWIN_USER_TEMP_DIR`; only with neither does it fall back to TMPDIR or `/tmp`. So on the Mac, todo's bare `mktemp` always lands in the system temp dir, whatever the test sets. Linux's `mktemp` uses TMPDIR.
- `opt/utilz/test/bridge.bats:204` runs every utility that declares an integration block in the command form the editor bridge builds. todo declares `input: file` and `flags: [--file]` (`opt/todo/todo.yaml`), so the test runs `utilz todo --file /nonexistent-probe.dat`. bridge.bats is the suite's first file, which fits the timing.
- `write_file` writes the new file to `$(mktemp)` and then `mv`s it onto `/nonexistent-probe.dat`. That `mv` cannot succeed, since `/` is not writable, and nothing removes the temp file.

If step 1 confirms it, todo leaks (item 2): its temp file goes beside the target, and is removed when the `mv` cannot happen. The bridge's probe then also stops reaching a write at all, since a write beside `/nonexistent-probe.dat` fails before anything is made.

## Design

dc, 19 Oct 2026, at `9bb32fa`. Size: XS.

1. **First, find whether todo or a test leaks.** Run the utilz suite's files one at a time and count the new `tmp.*` todo files in `$TMPDIR` after each, under bash 3.2. The file that leaves one names the test, which `--filter` then narrows down. Read todo's path for that call: whether `write_file` is reached and its `mv` fails, or is never reached after the `mktemp`, or the test kills todo between the two.
2. **If todo leaks, todo is fixed.** Its temp file goes in the target's own directory, `mktemp "$(dirname "$TODO_FILE")/.todo.XXXXXX"`, so the `mv` is a rename on one filesystem. A trap removes it on any exit before the `mv`. The same goes for `_prepend_file`.
3. **If only the test leaks, the test is fixed.** It runs todo in its own `$BATS_TEST_TMPDIR` with `TMPDIR` pointed there, so whatever todo leaves goes with the test's dir.
4. **Red by leftover count.** One test, in todo's suite (for 2) or in the file found (for 3), counts the `tmp.*` files a single call leaves in a `TMPDIR` of its own: one on main, none with the fix. Then the utilz suite under both bashes, with `$TMPDIR` listed before and after.
5. **Docs.** One CHANGELOG line under 2.14.1's Fixed. todo's version moves by a patch, if todo changes.
6. **Runs,** each booked with vc. Its own commit, after 0088's.
