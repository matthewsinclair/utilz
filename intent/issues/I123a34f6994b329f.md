Found by cc in the docs lean-out of 24 Nov 2026 (the dependencies and the count) and by dc (the licence line). Given to cc by vc under hv decision 23.

## What is wrong

- `opt/lnrel/lnrel.yaml` and `opt/cleanz/cleanz.yaml` say `dependencies: []`. lnrel needs GNU realpath for `-m` and `--relative-to` (`find_gnu_realpath`): `grealpath` from coreutils on macOS, and `realpath` on Linux. `cleanz --image` needs `exiftool` (`check_exiftool`). `utilz doctor` reads only the yaml, so it passes on a Mac where lnrel cannot run, and it says nothing about `cleanz --image`.
- The comment in `bin/utilz` at lines 62 to 64 says that there are fifteen utilities. bin/ links seventeen.
- The License sections of `opt/arngz/README.md`, `opt/cleanz/README.md` and `opt/syncz/README.md` say "Part of Utilz framework. Personal use.", each with its own copyright line. Utilz's LICENSE is MIT. Issue I2b133d8 is the same defect in ic's five READMEs.

## The fix

- `lnrel.yaml` declares `grealpath` (`platforms: [macos]`, required, `brew install coreutils`) and `realpath` (`platforms: [linux]`, required, `sudo apt install coreutils`), as `clipz.yaml` declares its tools for each platform.
- `cleanz.yaml` declares `exiftool`, `required: false`, for `--image`. clipz is in this tree, and cleanz finds it on PATH or at `$UTILZ_HOME/bin/clipz`. So `cleanz.yaml` names clipz in a comment and does not declare it as an external dependency.
- The comment in `bin/utilz` gives no count.
- Each of the three License sections says "MIT. See [LICENSE](../../LICENSE).", in the words of I2b133d8's fix. The README's own copyright line goes, because LICENSE holds the one copy. cleanz's README says that `cleanz.yaml` declares its dependencies, as arngz's README does.
- doctor's hand-written exiftool hint (`opt/utilz/lib/common.sh`, issue 0041) goes. It was there because no yaml declared exiftool, and with `cleanz.yaml` declaring it, doctor named exiftool twice. The first run's base TAP showed the hint, and its removal is the second commit.
