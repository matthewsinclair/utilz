utilz 2.14.8 from Homebrew with arngz 1.1.2, on rhadamanth (macOS, the Hammerspoon engine). main at 69171b43 carries arngz 1.1.3; this defect is in both.

`arngz discover` snaps each window it records to the desk's grid. A window whose frame begins off its display, as happens on a multi-monitor desk where a window sits on a monitor left of the origin, is **clamped into the edge cell** rather than left out or refused. `discover` says so in its report, exits 0, and saves the entry anyway. The next `apply` of that desk then fails the entry, because the clamped frame is not a size the app will take.

hv's run 69 (`Discover…` of zeophq, 2026-11-10T05:19:19Z, exit 0) reported:

```text
main desktop 1: notion.id "Meetings" spans part of a cell; snapped to 0,0 1x4, 1920px off
```

and run 70, an apply of the desk run 69 had just saved, on the same screens 20 s later, failed that entry:

```text
the window took 0,40 640x1089, not 0,40 225x1089
```

225 px is below Notion's minimum width, so the app refused it. The 1x4 cell the clamp produced is narrower than the window can be.

Repro: on a desk whose display has a monitor to its left, place a window on that left monitor, run `arngz discover --save <desk> --force`, then `arngz apply <desk>`. discover exits 0 and records the window in the edge cell; apply reports it failed and exits 1.

## Measured

Read first-hand by utilz-vc at main's head 69171b43, and from hv's `~/.local/state/menuz/menuz.log`.

- `opt/arngz/lib/plan.lua:1093`, `snap_axis`, the pure function that snaps one axis of a window to the grid:

  ```lua
  local a0 = clamp(round(a), 0, cells - 1)
  local b0 = clamp(round(b), a0 + 1, cells)
  ```

  where `a` is the window's start in cells from the display's origin. A frame starting left of that origin gives a negative `a`, which clamps to cell 0, and `b0` is then forced to at least one cell past `a0`. So a window 1920 px off the display is recorded as occupying the edge cell, and run 69's `0,0 1x4` with `1920px off` is exactly that arithmetic.
- The report already measures the distance and already says `spans part of a cell`, so `discover` holds the number it needs to refuse the entry. It lacks only the rule that says to.
- Run 70's Notion failure is this defect's downstream consequence, and it is one of the two failures that made run 70 exit 1 (the other being the fixed-size window issue filed beside this one).
- notion.id also failed in runs 39, 40 and 44 for a **different** cause, that its title bar is an `AXWebArea` arngz cannot take hold of to carry the window between desktops. That is not this issue and is not filed.
- The 1920 px offset is consistent with homere's left monitor (an HG560T34), but the observed frame was not kept by the run, so the exact origin is an inference from `snap_axis`'s arithmetic rather than a reading. The clamp itself is read from the source and is not in doubt.

Why it matters: `discover` is the one verb whose whole job is to record a desk that will apply. A desk it has just saved, applied straight afterwards on the same screens, is the test that tells a real defect from the environment, and this defect makes that test fail by writing an entry that cannot be placed. It also writes that entry into hv's Molt-matts working tree, where the desks live as `config/arngz/desks/`, so a bad record persists into a committed desk unless someone notices the report line.

## Fix

utilz-vc's recommendation: `discover` leaves out a window lying mostly off its display, and names it in its report with the distance it measured, so a desk records only what it can place. "Mostly" needs a threshold, and the recommendation is the window's **centre** falling outside the display: it is unambiguous, needs no measurement discover does not already make, and cannot be argued about at a boundary the way a percentage can.

Alternative, hv's to pick instead: record the window against the display it is actually on. A larger change, and right only where that display is itself part of the desk, so it does not help the common case of a window parked on a monitor the desk does not describe.

Not in this fix:

- Notion's `AXWebArea` title bar (runs 39, 40, 44), which stops arngz carrying the window between desktops.
- The fixed-size window case, filed as its own issue beside this one. Run 70 needs both fixed before it is clean.
