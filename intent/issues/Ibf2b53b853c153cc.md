Found by critic-shell's read of ST0031/02's tools/ci-suites on 23 Nov 2026, and filed on vc's word with ST0031/01's landing records.

## The gap

opt/prez/test/prez.bats runs in no CI job:

- test-linux and test-macos run every utility's suite through tools/ci-suites, which leaves prez out, because prez's black-box suites need what only the rust job installs: node 26, ffmpeg, poppler and, on Linux, a display;
- the rust job runs cargo build, cargo test and every crate/test/*.sh suite, and no bats;
- the clippy job only lints.

So a change that breaks prez.bats still passes CI. The suite runs only where someone runs `utilz test prez` by hand. The gap is older than tools/ci-suites: test-macos left prez out the same way, and its comment said nothing was lost.

## The fix (hv's scope)

Run prez.bats on CI, either:

- in tools/ci-suites, where prez is left out: its header says nothing in it builds the crate, and its arms that need the binary skip without one; or
- in the rust job, after its build, where the binary exists.

Neither has been run on a runner, so whether the suite passes there is unproven.

## When

vc recommends the next release, so as not to put this release's CI on a suite CI has never run.
