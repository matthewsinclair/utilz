`utilz use brew` removes the links in `~/.local/bin` before it asks whether a Homebrew copy would answer once they are gone. On a machine whose keg is installed but not linked, or where another copy comes first on PATH, it leaves no utilz on PATH, or the wrong one, and then prints the Homebrew install's version line as the tree the shell now reaches. Devbin's contract amendment A4 to `docs/dev-opt-brew.md` T5, agreed by the signatories on 26 Oct 2026 in intent-vc's wording, says: "`use brew` refuses, removing nothing, when no brew-managed copy would answer once the links are gone (the formula is not installed, its keg is not linked, or another copy comes first on PATH): it names each link it would have removed and the tree that link serves, why no Homebrew copy would answer, and the tool's own remedy (install or link the formula, or stay on dev or opt)."

## What

Line numbers are at `9027555d`, whose code HEAD has not changed.

- `install_verb_use brew` runs `tree=$(_install_brew_root) || return 1`, then `_install_remove_links "$bindir"` (`opt/utilz/lib/install.sh:1613-1614`). `_install_brew_root` (`:1478`) asks only that `$prefix/opt/utilz/libexec/bin/utilz` is executable (`:1484`). Homebrew keeps a keg's opt link when the keg is unlinked, so on an unlinked keg that test passes, the links go, and nothing answers.
- No name's first copy on PATH is asked about once its link is gone. The formula links every entry of the keg's bin (`bin.install_symlink Dir[libexec/"bin/*"]`, `packaging/homebrew/utilz.rb:31`), so whether Homebrew's copy answers is a question per link: each name the census removes must then resolve to the keg's copy.
- The refusals that do exist name neither the links nor the trees they serve, and their one remedy is `brew install`.

## Found

utilz-vc's read at `9027555d` on 26 Oct 2026, after hv ruled (a) through molt-vc (vc's decision 64) that Utilz's conformance to A4 goes into 2.14.4. utilz-vc saw, read-only on this Mac, that Homebrew keeps an unlinked keg's opt link, on the conflab and intent formulae. Devbin's issue 0235 is the same conformance for `devbin use brew`.

## Design

**Which copy counts as brew's.** The tree `_install_brew_root` names, `$prefix/opt/utilz/libexec`, which is the tree whose version line `use brew` prints. A name passes only when its first copy on PATH, once its link is gone, resolves (`_install_resolve`, every link followed) into that tree's `bin/`, each directory read by `pwd -P`. "Any tree `utilz_tree` calls brew" is not enough, since `use brew` prints that one tree's version line as the one the shell reaches. One predicate, `_install_answers_from <copy> <tree>`, answers "brew's copy answers", and bare `use` moves to it: its line "brew: no links, and <copy> (the Homebrew install) answers" (`:1519`) is printed only when the first `utilz` on PATH resolves into the tree `brew --prefix` names, found by the same finder. With no Homebrew install, or a first copy anywhere else, bare `use` prints "no links; <copy> answers, which is not the Homebrew install", as it does now. Until now it called any tree `utilz_tree` names brew the Homebrew install, so it could report brew for a copy whose version line `use brew` would not print.

**The finder.** `_install_brew_root`'s questions move into `_install_brew_find`, which prints nothing and answers either the prefix and the tree, or the reason there is none. `_install_brew_root` becomes that finder plus its refusals, word for word as now, so `_install_upgrade_brew` (`:1068`), its other caller, keeps what it prints. `use brew` no longer returns early on it: it takes the reason into its own refusal, which lists the links too.

**"Once its link is gone", computed without removing anything.** A filtered PATH for bash's own `type -P`, the lookup `install_link_health` uses, so they never differ on what PATH answers. `_install_path_without <dir>` walks PATH by its separators, keeping an empty entry (the shell reads it as the current directory), and drops each entry that resolves to `<dir>` by `pwd -P`, never by string, so a `~/bin` that links to `~/.local/bin`, and `/tmp` for `/private/tmp`, are dropped too (utilz-vc's W3). The lookup runs as `$(PATH="$filtered"; type -P "$name")`, so the assignment empties bash's table of remembered commands before the search.

**Which names are checked.** Every link `_install_remove_links` removes, and `utilz` itself. The census is read once, and the check and the removal take that one reading, through one predicate on a row's state (ours or broken, `_install_brew_removes`), so they cannot drift (IN-AG-HIGHLANDER-001). `utilz` is checked even when it has no link, as vc recommends, since the version line `use brew` prints claims that brew's copy answers `utilz`; so `use brew` with no links now refuses where another copy of `utilz` comes first. Where this differs from vc's recommendation, and why: the link directory is dropped from PATH only for a name whose link `use brew` removes there. `utilz` with no Utilz link is looked up on PATH as it stands, because a `utilz` in the link directory that is not a Utilz link stays where it is and goes on answering.

**A broken link's name** takes the same rule as any other, so a name the keg lacks blocks, and `use brew` never strands a name.

**The reasons, in the order they are decided.** Each is decided from what the tool already reads (`brew --prefix`, the opt link, `$prefix/bin/<name>` and PATH), never from Homebrew's own `var/homebrew/linked`. Homebrew's absence and the formula's hold for every name, so once either is found nothing after it is asked:

- **Homebrew is not installed**: `brew --prefix` answers nothing. Words, as now: "Homebrew is not installed (brew --prefix answered nothing)". Remedy: "Install Homebrew, then the formula: brew install matthewsinclair/utilz/utilz".
- **There is no Utilz formula**: `$prefix/opt/utilz/libexec/bin/utilz` is not executable. Words, as now: "there is no Homebrew install of Utilz under <prefix>". Remedy: "Install the formula: brew install matthewsinclair/utilz/utilz".
- Then, for each name, against the tree the finder named:
- **The keg lacks the name**: the tree's `bin/<name>` is not there, as for a utility newer than the brew release. Words: "the Homebrew install has no <name>". Remedy: "Upgrade the formula once a release carries it: brew upgrade utilz".
- Then the name's first copy on PATH once its link is gone. If it resolves into the tree's `bin/`, the name passes.
- **Another copy comes first**: the first copy is in a directory other than `$prefix/bin`, by `pwd -P`. Words: "another copy comes first on PATH: <copy>", followed by " (<tree> at <root>)" when the copy resolves to a Utilz tree's dispatcher, read by `install_tree_kind` and `utilz_tree`. Remedy: "Take each copy named above off PATH, or put <prefix>/bin before it (the sleeve's PATH order)".
- **The keg is not linked for the name**: `$prefix/bin/<name>` does not resolve into the tree's `bin/`, and nothing comes before it. Words: "the keg is not linked for <name>: <prefix>/bin/<name> does not resolve into it". Remedy: "Link the formula: brew link utilz".
- **Homebrew's bin is not on PATH**: what is left, with `$prefix/bin/<name>` the keg's own and nothing answering. Words: "Homebrew's bin, <prefix>/bin, is not on PATH". Remedy: "Put <prefix>/bin on PATH (the sleeve's PATH order)".

**The refusal.** It exits 1 and removes nothing. Its first line, on stderr, is "✗ use brew left the links in <bindir> as they were: <reason>", the reason being the one that holds for every name, or else "no Homebrew copy would answer once the links are gone". Then one line for each link it would have removed, in the census's order, naming the tree that link serves: "  <name> -> <tree> at <root>" from the census row, or "  <name> -> <target>, which has gone" for a broken link; then "  utilz (no Utilz link)" when `utilz` has none. A name that fails adds ": <reason>" to its line. Then each remedy its reasons call for, once, in the order above, and last, always, "  Or stay on dev or opt: utilz use dev|opt". The "<tree> at <root>" phrase is the bare report's, from one function the report and the refusal share.

**Where it lives (PFIC).** `_install_brew_verdict <name> <dropped-dir> <prefix> <tree>` is the verdict for one name, a function of those inputs and PATH: it prints nothing when brew's copy would answer, and `<reason><TAB><words>` otherwise. The coordinator, `_install_use_brew`, reads the census, asks for the verdicts, renders, and then refuses, or removes through `_install_remove_links`, which takes the census it is handed. Bash 3.2 throughout: no arrays, so no empty-array expansion under `set -u`, and no mapfile; a list is a newline- or TAB-separated string read with `while read`.

**Tests**, in `opt/utilz/test/use.bats`, each red on `9027555d`'s code and green with the fix; a test that also passes on the old code is proved by a mutation.

Its unlinked variant keeps the opt link and drops the `$prefix/bin` links, as `brew unlink utilz` does.
