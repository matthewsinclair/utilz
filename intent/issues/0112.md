`utilz use brew` removes the links in `~/.local/bin` before it asks whether a Homebrew copy would answer once they are gone. On a machine whose keg is installed but not linked, or where another copy comes first on PATH, it leaves no utilz on PATH, or the wrong one, and then prints the Homebrew install's version line as the tree the shell now reaches. Devbin's contract amendment A4 to `docs/dev-opt-brew.md` T5, agreed by the signatories on 26 Oct 2026 in intent-vc's wording, says: "`use brew` refuses, removing nothing, when no brew-managed copy would answer once the links are gone (the formula is not installed, its keg is not linked, or another copy comes first on PATH): it names each link it would have removed and the tree that link serves, why no Homebrew copy would answer, and the tool's own remedy (install or link the formula, or stay on dev or opt)."

## What

Line numbers are at `9027555d`, whose code HEAD has not changed.

- `install_verb_use brew` runs `tree=$(_install_brew_root) || return 1`, then `_install_remove_links "$bindir"` (`opt/utilz/lib/install.sh:1613-1614`). `_install_brew_root` (`:1478`) asks only that `$prefix/opt/utilz/libexec/bin/utilz` is executable (`:1484`). Homebrew keeps a keg's opt link when the keg is unlinked, so on an unlinked keg that test passes, the links go, and nothing answers.
- No name's first copy on PATH is asked about once its link is gone. The formula links every entry of the keg's bin (`bin.install_symlink Dir[libexec/"bin/*"]`, `packaging/homebrew/utilz.rb:31`), so whether Homebrew's copy answers is a question per link: each name the census removes must then resolve to the keg's copy.
- The refusals that do exist name neither the links nor the trees they serve, and their one remedy is `brew install`.

## Design

**Which copy counts as brew's.** The tree `_install_brew_root` names, `$prefix/opt/utilz/libexec`, which is the tree whose version line `use brew` prints. A name passes only when its first copy on PATH, once its link is gone, resolves (`_install_resolve`, every link followed) into that tree's `bin/`, each directory read by `pwd -P`. "Any tree `utilz_tree` calls brew" is not enough, since `use brew` prints that one tree's version line as the one the shell reaches. One predicate, `_install_answers_from <copy> <tree>`, answers "brew's copy answers", and bare `use` moves to it: its line "brew: no links, and <copy> (the Homebrew install) answers" (`:1519`) is printed only when the first `utilz` on PATH resolves into the tree `brew --prefix` names, found by the same finder. With no Homebrew install, or a first copy anywhere else, bare `use` prints "no links; <copy> answers, which is not the Homebrew install", as it does now. Until now it called any tree `utilz_tree` names brew the Homebrew install, so it could report brew for a copy whose version line `use brew` would not print. Bare `use` so gains a call to brew when there is no link, and a missing brew says nothing and changes nothing about its exit status.

**The predicate asks first that the copy is there.** `_install_answers_from` starts with `[[ -e "$copy" ]] || return 1`. The verdict's last step hands it `$prefix/bin/<name>`, which nothing has looked up, and `_install_resolve` follows links with no bound, so a link loop there (`alpha -> alpha`, or `a -> b -> a`) would hang `use brew`. A path that is not there answers nothing, and `-e` fails on a loop as well (utilz-vc's P2). Before this change every caller handed it a `type -P` hit, which exists.

**The finder.** `_install_brew_root`'s questions move into `_install_brew_find`, which says nothing of its own: it answers on stdout either the prefix and the tree, or the reason there is none with its words, and returns 1 for a reason. `_install_brew_root` becomes that finder plus its refusals, word for word as now apart from the no-Homebrew words below, so `_install_upgrade_brew` (`:1068`), its other caller, keeps what it prints, and a test pins those words. `use brew` no longer returns early on it: it takes the reason into its own refusal, which lists the links too. The finder reads the tree from `brew_opt_root <prefix>`, new beside `brew_stable_home` in `opt/utilz/lib/common.sh`, which is the one spelling of `<prefix>/opt/utilz/libexec`; `brew_stable_home` (`common.sh:1026` at `1b6eb078`) reads it too, and so does the finder, which spells that path at `install.sh:1484` and `:1489` today.

**"Once its link is gone", computed without removing anything.** The coordinator filters PATH once per run: `_install_path_without <dir>` walks PATH by its separators, keeping an empty entry (the shell reads it as the current directory), and drops each entry that resolves to the link directory by `pwd -P`, never by string, so a `~/bin` that links to `~/.local/bin`, and `/tmp` for `/private/tmp`, are dropped too (utilz-vc's W3). An entry written `~` or `~/...` is read as `$HOME` followed by the rest of the entry, when HOME is set, before it is resolved, and kept as written: bash's own lookup expands a leading `~` in a PATH entry, so `~/.local/bin` in PATH is the link directory and is dropped. Each name's verdict is handed the path it searches: the filtered PATH for a name whose link `use brew` removes, and `$PATH` as it stands for `utilz` with no Utilz link. The verdict runs bash's own `type -P`, the lookup `install_link_health` uses, as `$(hash -r && PATH="$search" type -P "$name")`: the subshell first empties bash's table of remembered commands, since bash 3.2 answers `type -P` from that table even under a PATH set for the one command, and the search path is set for that command alone, so the verdict reads no ambient PATH. An assignment, `PATH="$search";`, would empty the table too, but shellcheck flags a change made inside a subshell (SC2030, SC2031), and CI's shellcheck fails on it. The drop rule is in one place, and each PATH entry is resolved once a run, not once a name.

**Which names are checked.** Every link `_install_remove_links` removes, and `utilz` itself. The census is read once, and the check and the removal take that one reading, through one predicate on a row's state, `_install_is_utilz_link` (ours or broken). The same predicate replaces the inline test of that state in `_install_point_links`' loop and in the bare report's count of links, so what `use brew` removes, what `use dev|opt` repoints and what the report counts cannot drift (IN-AG-HIGHLANDER-001). `utilz` is checked even when it has no link, since the version line `use brew` prints claims that brew's copy answers `utilz`; so `use brew` with no links now refuses where another copy of `utilz` comes first. The link directory is dropped only for a name whose link `use brew` removes there, and `utilz` with no Utilz link is looked up on PATH as it stands, because a `utilz` in the link directory that is not a Utilz link stays where it is and goes on answering.

**A broken link's name** takes the same rule as any other, as A4's text has it, so a broken link whose name the keg lacks blocks the switch too. That name is already stranded: the link answers nothing now, so removing it takes no answer away, and no release need ever carry the name. Its remedy is therefore to remove the dead link, never to wait for a release.

**The reasons, in the order they are decided.** Each is decided from what the tool already reads (`brew --prefix`, the opt link, `$prefix/bin/<name>` and PATH), never from Homebrew's own `var/homebrew/linked`. Homebrew's absence and the formula's hold for every name, so once either is found nothing after it is asked. Every case lands in exactly one reason:

- **Homebrew is not installed, or is not on PATH**: `brew --prefix` answers nothing. The tool finds brew by `INSTALL_BREW`, which is `brew` on PATH unless set, so brew off PATH and no Homebrew read the same, and the words now say so. Words: "Homebrew is not installed, or is not on PATH (brew --prefix answered nothing)", with the brew it ran in place of `brew`. Remedies: "Install Homebrew, then the formula: brew install matthewsinclair/utilz/utilz", then "Or, if Homebrew is installed, put its bin on PATH, in your shell config: eval "$(<brew's prefix>/bin/brew shellenv)"". The tool does not probe Homebrew's standard prefixes to tell those cases apart, since a probe would read the real Homebrew in every test.
- **There is no Utilz formula**: `$prefix/opt/utilz/libexec/bin/utilz` is not executable. Words, as now: "there is no Homebrew install of Utilz under <prefix>". Remedy: "Install the formula: brew install matthewsinclair/utilz/utilz".
- Then, for each name, against the tree the finder named:
- **The keg lacks the name**: the tree's `bin/<name>` is not there, as for a utility newer than the brew release. Words: "the Homebrew install has no <name>". Remedy, for a link into a tree: "Upgrade the formula once a release carries it: brew upgrade utilz"; for a broken link: "Remove the dead link: rm <bindir>/<name>", a line for each such link, its path printed with `printf '%q'` so a link directory whose path holds a space is a command that runs as printed.
- Then the name's first copy on the path it searches. If it resolves into the tree's `bin/`, the name passes.
- **Another copy comes first**: the first copy is in a directory other than `$prefix/bin`, by `pwd -P`. Words: "another copy comes first on PATH: <copy>", followed by " (<tree> at <root>)" when the copy resolves to a Utilz tree's dispatcher, read by `install_tree_kind` and `utilz_tree`. Remedy: "Take each copy named above off PATH, or put <prefix>/bin before it (the sleeve's PATH order)".
- **The keg is not linked for the name**: a first copy in `$prefix/bin` that does not resolve into the tree's `bin/`, or no copy at all with `$prefix/bin/<name>` not into it, a link loop there included. Words: "the keg is not linked for <name>: <prefix>/bin/<name> does not resolve into it". Remedy: "Link the formula into brew's bin: brew link utilz".
- **Homebrew's bin is not on PATH**: what is left, with `$prefix/bin/<name>` the keg's own and nothing answering, as where brew is found by `INSTALL_BREW` or by a PATH entry other than its bin. Words: "Homebrew's bin, <prefix>/bin, is not on PATH". Remedy: "Put brew's bin on PATH, in your shell config: eval "$(<prefix>/bin/brew shellenv)"".

**A verdict that cannot finish refuses.** The coordinator reads each verdict as `verdict=$(_install_brew_verdict ...) || { error "use brew could not check <name> (its check exited <status>), so it removed nothing"; return 1; }`, so a check that fails is never read as a pass, and nothing is removed (IN-AG-NO-SILENT-001).

**One source for each remedy.** Each brew command a remedy names is worded once, beside `print_path_remedy` in `opt/utilz/lib/common.sh`, so each remedy is worded the same wherever it is named: `brew_install_command`, `brew_link_command`, `brew_upgrade_command`, and `brew_shellenv_command [<prefix>]`, which is the concrete `eval "$(<prefix>/bin/brew shellenv)"`, and names `<brew's prefix>` in its place when given none or an empty one. The refusal reads them, and so does every place that words the same remedy now: `print_path_remedy` (for `utilz doctor` and `utilz emacs doctor`), whose fallback when brew answers no prefix becomes an empty prefix (`common.sh:1154` at `1b6eb078`), `_install_brew_root`'s refusal, upgrade's refusal for a tree it cannot name (`install.sh:977`), `install_refuse_keg` (`:748`), and doctor's notes on an old or missing manifest (`common.sh:1935`, `:1950`, `:1971`). What each of those prints does not change, and the run's words phase compares each of them byte for byte, `print_path_remedy` with no prefix included.

**The refusal.** It exits 1 and removes nothing, and every line of it goes to stderr. Its first line is "✗ use brew left the links in <bindir> as they were: <reason>", the reason being the one that holds for every name, or else "no Homebrew copy would answer once the links are gone". Then one line for each link it would have removed, in the census's order, naming the tree that link serves: "  <name> -> <tree> at <root>" from the census row, or "  <name> -> <target>, which has gone" for a broken link; then "  utilz (no Utilz link)" when `utilz` has none. A name that fails adds ": <reason>" to its line. Then each remedy its reasons call for, once, in the order above, and last, always, "  Or stay on dev or opt: utilz use dev|opt". The "<tree> at <root>" phrase is the bare report's, from one function the report and the refusal share.

**Where it lives (PFIC).** `_install_brew_verdict <name> <search-path> <prefix> <tree>` is the verdict for one name, a function of those inputs: it reads no ambient PATH, prints nothing when brew's copy would answer, and prints `<reason><TAB><words>` otherwise. The coordinator, `_install_use_brew`, reads the census once, filters PATH once, asks for the verdicts, renders, and then refuses, or removes through `_install_remove_links`, which takes the census it is handed. Bash 3.2 throughout: no arrays, so no empty-array expansion under `set -u`, and no mapfile; a list is a newline- or TAB-separated string read with `while read`.
