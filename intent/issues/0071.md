## What

hv, 18 Oct 2026, looking at menuz's Desks… flyout: Discover…'s default name should be "the name of the currently selected desk" rather than `today`, and the Desks… flyout should "put a tick mark" beside that desk.

arngz's record of the current desk is its own issue. This is menuz's half.

## Measured

18 Oct 2026, at `2f46784`.

- A param's `default:` is literal text (`MenuzKit/Sources/MenuzKit/Form.swift:47`). Only `choices:` is realised when the form opens.
- No entry can mark an item checked: nothing in `native/macos/Menuz/Menuz` sets an item's state.

## Fix

Ruled 18 Oct 2026, in hv's stead:

1. **A default the shell fills in.** A `default:` holding a `$` or a backtick is realised by the login shell when the form opens, as a `choices:` shell line is. The field shows a pending state until the shell answers, and a failure in the field. A default with neither stays literal.
2. **A tick.** `checked:` on an `each` is realised with the menu's labels, in the same single `zsh -ilc` at every open. The each's items whose line equals the realised value are ticked, and `menuz render` shows the tick. The validator refuses `checked:` anywhere but an `each`.
3. **hv's file,** once arngz can say the current desk:
   - Discover…'s `desk` gets `default: "$(arngz current)"`, with `required: true`, so an empty name is refused in the form.
   - The Desks… `each` gets `checked: "$(arngz current)"`.
4. **From 0069's last critic-swift pass,** since this change touches the same files:
   - A file whose first entry is a separator draws two lines under the identity row. Treat the top as 0069 treats the tail, or say in `help/menuz.md` that a file need not start with one.
   - Pin a separator that ends the last submenu, and refusals shown with no file loaded, with a test each.
   - The wording "a file that ends in a separator" means the menu's own last entry.
   - Name a placed app item's binding `item`, not `tail`.

`help/menuz.md` and the CHANGELOG describe it. menuz goes from 0.2.0 to 0.3.0.

## Resolution

Fixed in `56e0c90` (18 Oct 2026). ic landed it under hv's word in ic's session ("Ok, crack on under instructions from VC.", 07:42:13Z), after vc's read, and pushed it to local. All four points are in:

1. **A default the shell fills in.** A `default:` holding a `$` or a backtick is realised by the login shell when the form opens, waiting at most `realise` seconds. The field starts empty, and Run waits on "the default is not read yet" while nothing is typed there; what has been typed is never overwritten. A default the shell cannot give is a note under the field, beside any refusal, and a line in the log under the item's label. A default with neither a `$` nor a backtick stays literal.
2. **A tick.** `checked:` on an `each` is realised with the labels, in the same single `zsh -ilc`, under `<path>#checked`. A literal is used as written and never sent. The item whose line equals the answer is ticked, and `menuz render` prints `✓ ` before it. The validator refuses `checked:` anywhere but an `each`.
3. **hv's file waits.** The `arngz` on hv's PATH is Homebrew's 2.14.0 keg, arngz 1.0.1, which has no `current`, and only arngz 1.1.0 writes the record. hv's login shell finds /opt/homebrew/bin ahead of ~/.local/bin, so `utilz use dev` does not change that; the next release does. A `$(...)` that exits 1 fails its whole string, so the lines carry fallbacks: `checked: "$(arngz current || true)"`, and `default: "$(arngz current || echo today)"` with `required: true`, as the shipped example does.
4. **0069's last critic notes.**
   - A separator that starts the menu, or follows another at its top level, draws no line of its own.
   - A separator ending the last submenu, and refusals shown with no file loaded, are pinned by a test each.
   - The wording names the menu's own last entry.
   - A placed item's binding is `item`.

When the shell gives no answer, a form now says what the shell did: no answer within the cap, the login shell could not start, or it exited before it answered. One helper realises, reads and logs both a `choices:` line and a default, so a failed `choices:` line is logged too. menuz goes from 0.2.0 to 0.3.0.
