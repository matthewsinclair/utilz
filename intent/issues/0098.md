## What

`showreel build` names each new revision one past the highest it finds in `_out/`, and its module's rule is that builds never overwrite each other (`deliver.rs:214-217`). The listing it counts from takes an `_out/` it cannot read as empty: `Stem::revisions` (`deliver.rs:190-210`) reads it with `read_dir(..).into_iter().flatten().filter_map(Result::ok)` (`:194-197`), so a read that fails, or an entry that fails, is no revision at all. `next()` (`:218-226`) then names revision 001, and `build` writes it with `std::fs::write` (`build.rs:265`), which truncates a file already there. An `_out/` that can be written but not listed (mode `0300`) is enough: the build succeeds, and a delivered 001 is replaced with nothing said. `prune` counts from the same listing, so `--keep` then drops nothing and says nothing. cc found it on 20 Oct 2026 while designing 0096's point 9, which ends the same silence in `video.rs`'s sweep. vc made it its own issue, cc's, for 2.14.2 after 0096 (20 Oct), and asked that the design say by name whether `prune`'s size sum and `slot_files`' `is_file()` are in it (22 Oct).

## Where, by reading (main at `b517e491`)

- **The listing**: `Stem::revisions` (`deliver.rs:190-210`), above. Its callers are `next()` (`:222`) and `prune` (`:355`).
- **The write**: `build::run` makes `_out/` (`build.rs:256`), asks `next()` for the name (`:262`) and writes it with `std::fs::write` (`:265`). `create_dir_all` succeeds on an `_out/` that already exists, whatever its mode, so nothing before the write notices.
- **The slot's video**: `slot_files` (`deliver.rs:335-344`) takes a revision's video with `Path::is_file` (`:341`), which reads an error as absent, so `prune` would drop a revision's HTML and leave behind a video it could not check, against the module's own rule that a slot is one revision (`:333`, ST0021 AC-03.5). `is_file` also follows a link, so a video that is a dangling link is left behind the same way.
- **The size sum**: `prune`'s warning for more than five revisions sums their slots' sizes with `filter_map(|p| std::fs::metadata(p).ok())` (`:372`), so a size it cannot read counts as nothing and the total prints low, the silence 0096's point 9 ends for `video`'s and `build`'s own sizes.

## Design

cc, 22 Oct 2026, at `b517e491`. Size: M. It lands after 0096 and is built on 0096's landing, whose `deliver::size_of` and `deliver::megabytes` it uses. Read and approved by vc, 22 Oct, with point 5 taken; point 9's two in `plan.rs` became their own issue, 0099. critic-rust read v1 (22 Oct): no compile risk by reading, and two CRITICAL red-control gaps, both taken (points 5 and 6): nothing tested which write `write_next` asks for, or `--out`'s overwrite, and an overwrite that does not truncate stayed green. Of its five recommendations, v2 takes four: every size not read is named (6 (d)), the build test asserts the overwrite first (6 (b)), one clone fewer, and `video.rs`'s own writer folded into `deliver::write` (point 5, for vc's read). The fifth, `video`'s rename replacing an orphan video, is its own issue (point 9). critic-rust then read the v1-to-v2 change (22 Oct): no compile risk by reading, nothing CRITICAL or WARNING, and two points, both taken in v3: the never-replaces tests assert the kept bytes before the refusal, so a mutation shows the bytes assertion red (6 (e) and (f)), and run R gains a mutation that leaves `--out` unwritten, which only (g)'s content assertion can catch.

1. **A read of `_out/` that fails is refused, never an empty directory.** `Stem::revisions` returns `Result<Vec<(u32, PathBuf)>, Failure>`: a `read_dir` that fails, or an entry that does, refuses, naming the directory, as `admit.rs:223-250` does. The listing has one home, `deliver::entries(&Path) -> std::io::Result<Vec<PathBuf>>`, which `revisions` and 0096's `sweep_partials` (`video.rs`) both call, each mapping the error into its own words, so the sweep keeps its message and the two listings cannot drift. A `Stem::Fixed` has no revisions and reads nothing, as now. A missing `_out/` refuses too, which no caller meets, since `build` makes it first. `next()` returns `Result<PathBuf, Failure>`, and `build` passes the refusal on before it writes anything. The words: `cannot read <dir> for the next revision's number: <error>`, with the remedy `make the directory readable, or name the output with --out`.
2. **`prune` passes the refusals on before anything is deleted.** `prune` returns `Result<(Vec<PathBuf>, Vec<String>), Failure>`. It lists through `revisions` (point 1) and collects each old slot through `slot_files` (point 3) before it returns a single path, so a refusal leaves every revision where it is. `build` already refuses on a removal that fails (`build.rs:289`).
3. **`slot_files`' `is_file()` is in.** A slot is one revision (AC-03.5), so the video that goes with a pruned HTML is found by its directory entry, not by what the entry points to: `std::fs::symlink_metadata`, where a video that is not there (`NotFound`) is absent and any other error refuses, naming the video and the revision it goes with. The remedy names what is missing: the directory must be readable and searchable. A dangling link is then pruned with its slot rather than left behind. `slot_files` returns `Result<Vec<PathBuf>, Failure>`. Its other consumer is the size sum (point 4).
4. **`prune`'s size sum is in.** It reads each size with 0096's `deliver::size_of`, so a size it cannot read is said in `size_of`'s words and the total is unknown rather than low: the warning prints it with `deliver::megabytes`, `? MB` for an unknown total. One size reader and one printer, as 0096 leaves them; the total then prints to one decimal place, as the summaries do.
5. **A counted revision is written so that it cannot replace another (vc took it, 22 Oct).** Once point 1 lands, the listing no longer misses a revision it cannot read, but two builds of one reel at the same time can still take the same number, and the second's `std::fs::write` replaces the first's. Writing a counted revision with `OpenOptions::new().write(true).create_new(true)` makes the module's rule hold by construction: a file already at that name refuses (`AlreadyExists`, and only on a fresh write), saying what is known: `cannot create <path>: a file is already there, and a build never replaces one`, with the remedy `if another build of this reel was running, build again; if not, move that file aside`. The wording names no cause, since a pattern whose literal text names a directory can also make `next` name a file the listing does not count (critic-rust). One function beside `next()`, `Stem::write_next(&self, out_dir, bytes) -> Result<PathBuf, Failure>`, names the revision and writes it, and `build` calls it when there is no `--out`. A fixed name and `--out` keep overwriting, as they do by design (`deliver.rs:182-183`). `video`'s own writer for its frames and `frames.tsv` (`video.rs`, a private `write`) becomes `deliver::write(path, bytes, false)`, so the `cannot write` wording has one home in showreel (critic-rust's read of v1, folded in for vc's read; the frames' remedy becomes `check the path`). Holding the module's rule at the write is the one place that guarantees it, against an unreadable `_out/` and a race alike (vc).
6. **Red first**, each new test red by a one-line mutation, one at a time. (a) `revisions` and `next()` refuse an `_out/` at mode `0300` (writable, not listable), naming it, with 0095's rule for root: a listing that succeeds under that mode fails the test, saying it cannot run there. The mode is restored before any assertion, so the guard can remove the directory. Red with the listing's error taken as an empty directory, as main takes it. (b) The overwrite itself, through `build::run`: a reel is built once, its 001 is rewritten to known bytes (a delivered revision), `_out/` goes to `0300`, and the reel is built again. The candidate refuses and 001 keeps its bytes; main builds and replaces them. The bytes are asserted before the refusal, so main's red reads as the overwrite itself (critic-rust). This is the test that is red on main, in the run's phase that runs it on main and on the candidate. (c) `slot_files`: a revision whose video is a dangling link is pruned with it, red with `symlink_metadata` back on `is_file`; and a video it cannot check (`_out/` at `0600`, listable but not searchable, with the rule for root as in (a)) is refused by name, red with the error arm taken as absent. (d) The size sum: six revisions, two of whose videos are dangling links, print `? MB` and name both sizes not read. Red with the sum skipping a size it cannot read, as main does; and red with a sum that stops at the first size it cannot read, as `Option`'s sum does, since every size is read before the sum (critic-rust). (e) A fresh `write` refuses a file already at its name and leaves its bytes, red with `create_new` taken out; an overwriting one replaces a longer file whole, red with `truncate` taken out (critic-rust). (f) `write_next` asks for the right write (critic-rust): a fixed name written twice holds the second write whole, red with a fresh write asked for; and a counted revision whose name the listing does not count, through a prefix naming a directory below `_out/`, is refused and keeps its bytes, red with an overwrite asked for. (g) `build --out` over a file already there replaces it, red with a fresh write asked for, and red at its content assertion with the `--out` write left out.
