## Fix-forward: the row's icon (19 Oct 2026)

**The finding.** hv looked at menuz 0.4.0 (`6583e70`) and said "LGTM!" to the four checks, but the screenshots show the top row with no icon, though masthead.yaml says `icon: app` and help/menuz.md and the CHANGELOG say "with menuz's icon" (vc, 08:38Z).

**Read so far.** arca_swift 0.1.1's `MastheadRow.apply` (`MastheadRow.swift:89` to `:94`) sets the title, the subtitle and `item.image = masthead.icon == .app ? icon.map(sized) : nil` in one pass, at init and at each open of its own menu, and its public init's `icon` is `{ NSApplication.shared.applicationIconImage }` (`:43`). The title and subtitle are right, so the image was set in the same pass, to nil or to one that draws nothing. masthead.yaml parses (`icon: app`, no refusal in menuz.log). Menuz.app and Gtools.app carry the same icon keys and files: `CFBundleIconFile` and `CFBundleIconName` AppIcon, AppIcon.icns, AppIcon in Assets.car, LSUIElement. The difference is code. Gtools.app sets `NSApp.applicationIconImage` itself at launch (`GtoolsApp.swift:95` to `:98`), and so does arca_swift's example (`ArcaMastheadExample/main.swift:17`), so both rows known to draw an icon draw one their app set (gtools-ic, 19 Oct). menuz is the first adopter to leave AppKit's default, which on this Mac (macOS 27.0.1) the row shows as nothing.

**The red test,** in `MenuzTests/IdentityRowTests.swift`, against today's code: the row `MenuzMasthead.row` makes has an image, 32 by 32, and drawn into a 32 by 32 bitmap it colours at least one pixel. Its failure message measures `NSApp.applicationIconImage` (nil, or its size and its representations' classes), which gtools-ic takes to arca_swift as an issue after the Gtools cut. If the test passes, the image is set and draws, so the cause is the menu's drawing, and that comes back to vc before any code.

**The fix.** `MenuzMasthead.row`, the one function every row is made through (the app's, at its first capture, and `--render`'s), sets `NSApplication.shared.applicationIconImage` to the bundle's AppIcon (`bundle.image(forResource: "AppIcon")`, the AppIcon.icns actool writes) before it makes the row. It is there, not in `applicationDidFinishLaunching`, because the launch path is skipped under the XCTest host (`MenuzApp.swift:66` to `:69`), so only a fix the row's function makes can be seen by the test. A bundle with no AppIcon is logged through `log`, once per row, and the default is left. It also gives menuz's alerts its icon, as Gtools' comment says of its own.

**Not changed.** help/menuz.md, the CHANGELOG and masthead.yaml already say what the row then shows. menuz's version, 0.4.1 since 0074, is vc's and hv's to say: this proposes no bump and no new CHANGELOG line, since 2.14.1's Added entry for 0073 already promises the icon and no release has shipped without it.
