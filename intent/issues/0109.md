## What

hv ruled on 25 Oct 2026, relayed to utilz-vc, that ` at <root>` comes off the version line: "That info is idiotic. Why would that ever be necessary when you can just type of which it!?" This is devbin-vc's amendment A3 to the dev, opt, brew contract (devbin's `docs/dev-opt-brew.md` T4; draft `contract-A3.md`, sha256 b19ffcb9...21a0), and Utilz has said SAME to it. It goes in 2.14.4, under hv's one-next-release ruling.

`utilz --version`, `utilz version` and `utilz doctor`'s first line become `utilz <version> (<tree>, <sha12>[+dirty])`. `(dev, unknown)`, `(unknown)` and `(<tree>, old manifest)` keep their parenthesis and lose only the tail. The line names no path: where the running copy lives is the answer `command -v utilz` gives. A reader reads up to the closing parenthesis and ignores anything after it, so a reader of the old shape still reads the new one.

hv ruled that A3's doctor clause goes in too (utilz-vc's decision b8cb0870). A3's T4, as devbin's land220 (58ccf8c7, line 52) and `contract-A3.md` give it: "Doctor prints the same line, and names a path only where a check that fails is about one." `utilz doctor` already opens with the version line. On its other passing and noted lines it names a path, which the clause forbids:

- `✓ UTILZ_HOME=<root>` (UTILZ_HOME check);
- `✓ dev: the git checkout at <root>`, `✓ <tree>: an install at <root>, with an old manifest (see install integrity)` and `✓ <tree>: an install at <root>` (which-tree check);
- `✓ utilz is on $PATH via <link>` (PATH check);
- `ℹ The manifest at <root> is in the old form, ...; 'brew upgrade utilz' replaces it once the next release is out` (install integrity, an old keg: noted, not counted, so it is not a failing check).

Each keeps its words and loses the path. A line on a failing check keeps its path, which the clause allows: UTILZ_HOME pointing at a missing directory, a tree Utilz cannot name, dev with git unreadable, the `chmod +x` remedy, the PATH remedy, an old or unreadable opt manifest, and the link-health renderer shared with `use` (`install_link_health_render`, errors only). `use`'s report and `upgrade`'s output are not doctor, and the clause does not reach them. The one doctor line they share is the version line.

## Fix

- `utilz_version_line` (`opt/utilz/lib/common.sh`) prints `utilz %s (%s)` with no root.
- `utilz_tree_root`'s only caller is the version line, so it is deleted (Highlander, no dead code). `brew_stable_home` keeps its other callers, so it stays.
- Tests that pin the tail are rewritten to pin the new whole line, not kept alongside the old ones. The affected suites are version_dispatch, common_lib, tree, install_e2e, install_guards, upgrade, use and dispatcher, plus any others a sweep of every file in opt/utilz/test finds. tree.bats's tests that a brew line names the opt link rather than the keg become tests that the line names no path at all.
- Every doc and help text that shows ` at <root>` is updated: README, help/utilz.md, docs/releasing.md and the comments in common.sh.
- Doctor's passing and noted lines listed above drop their path, in `run_doctor` (`opt/utilz/lib/common.sh`). Its failing lines are unchanged.
- The tests that pin those lines are rewritten. tree.bats's old-keg test asserts the noted line with no path, and refutes the path on it. install_guards.bats AT15 read `UTILZ_HOME=<inst>` off doctor to prove a dispatched child sees the prefix, not the inherited source; it now reads the tree on doctor's version line, `(opt, ` and never `(dev, `. Every file in opt/utilz/test is swept for a pin on any of these lines, assert or refute.
- A CHANGELOG entry goes under 2.14.4.

The tests are proven red on main first, then green. Landing waits until A3 is in devbin's docs and utilz-vc has read the bytes.
