## Summary

AT20's forwarded leg (`opt/prez/crate/test/acceptance.sh:1412-1419`) runs `at20-window-probe.mjs` and maps any non-zero exit to one verdict: "the forwarded window did NOT inherit -- AC19(d) describes behaviour this build does not have, so the criterion is now wrong and needs re-measuring". **The probe exits 1 for two different events**: a window that opened and measured wrong (`at20-window-probe.mjs:181-186`), and no new window at all inside its 10s poll (`at20-window-probe.mjs:100-106`). Only the first is evidence about AC19(d). The second measured no geometry, and the harness still reports it as a finding against the criterion.

## How it was found

2026-09-14, CI run 34843482745 on 4e2b3b5, job Rust (macos-latest), which hv surfaced. The probe printed `FAIL forwarded: no NEW page target on port 9372 after 10s (excluding 1); saw types [browser_ui, background_page, page, service_worker]`, and the harness then declared the criterion wrong. Nothing supports that verdict:

- The runner image was the one the last green run used (macos-26-arm64 20260907.0351.1, run 34592977422), where the forwarded window appeared within half a second and inherited.
- No prez source changed between the two runs. The only crate change is ff13fbe, AT09's src walk, and AT20 runs `target/release/prez` directly (`acceptance.sh:55`), so no shim change is in its path.
- The three legs before it passed in the same job: the default window, the override, and the first shared-profile window.
- AT20 passed locally on the same prez source, in cc's gate run for 0024 and in vc's full run on 4e2b3b5.

## What it costs

A failure that names the wrong cause sends its reader to re-measure AC19(d) against a Chrome that did not change. It also cannot tell a one-off from a Chrome that genuinely stopped forwarding, because on the no-window path it shows neither `prez present`'s own output (`$WORK/at20-present.log`, written by all three launches and never printed) nor the URLs of the targets it saw, only their types.

## Fix direction

- The probe exits with a code of its own when no new page target appears, distinct from a measured failure, and lists every target it saw by type and URL.
- The harness reports that code as what it is: the forwarding launch opened no window, so AC19(d) was not measured. It prints `at20-present.log` beside it, and it stays a failure, never a skip.
- A measured failure keeps today's verdict, because that one is evidence about the criterion.
- No new check is minted for the harness itself: a check whose subject is the probe is a test of a test, which hv's standing direction (2026-09-11) rules out. The fix is proved once, by driving the probe where no new page target can appear, and both outputs, HEAD's and the fix's, go in the commit.

**This does not make the forwarding leg pass when Chrome drops a forwarded launch.** Whether the 4e2b3b5 failure recurs is a separate question, and a re-run of the failed job answers it; that is hv's call.

## Severity

Low. Test-harness only, and the run failed loudly. It named the wrong cause, which costs a diagnosis, not a defect in prez.
