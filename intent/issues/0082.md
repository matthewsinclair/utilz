## What

A test should write nothing outside its own temp dirs, and read none of the user's own configuration. Four suites break that, through tools that keep their state in the user's home or session:

- **syncz.** Its nine unison tests (`opt/syncz/test/syncz.bats:882` to `:1009`) run unison through `syncz --bidi` with UNISON unset. Its other bidi tests (`:540` to `:777`) go through `run_syncz`, whose `--backend rsync` (`:12`) keeps them off unison. So unison keeps its archives and its log in the user's own unison dir: `~/.unison` on Linux, and `~/Library/Application Support/Unison` on this Mac. One run of the suite leaves 18 archives there, two per sync. unison also reads `default.prf` from that dir, though the roots are on the command line, so the tests run under the user's own unison preferences. Where the file is missing, unison makes one.
- **cryptz.** Its round trip (`opt/cryptz/test/cryptz.bats:112`) runs `gpg --list-keys`, then `cryptz encrypt` to cryptz's default recipient (`opt/cryptz/cryptz:26`), on the user's own gpg home. Where that key is missing, gpg's auto-key-locate looks it up over the network (WKD, through dirmngr), and the dirmngr it starts outlives the suite. Where the key is present, the test encrypts with the user's real key.
- **macoz.** On macOS, three background tests set the picture of every desktop through `osascript` (`opt/macoz/macoz:146`): `opt/macoz/test/macoz.bats:67`, `:88` and `:111`. So each run of the suite changes the user's wallpaper.
- **clipz.** The copy tests and the round trip (`opt/clipz/test/clipz.bats:60`, `:65` and `:87`) write the user's clipboard, and `:76` reads it.

Every run of these suites collects this: `utilz test <name>`, the estate gate (`tools/test-estate`), the release's dry run and its cut, and dc's kovacs legs. CI's runners are fresh each time, so there it is harmless.

The helper already holds the one door for a test's own dir. `setup()` (`opt/utilz/test/test_helper.bash:60`) makes `$BATS_TMPDIR/utilz-test-<epoch>-<pid>-<random>` and moves into it, and `teardown()` (`:74`) removes it. 28 of the 32 suites that load the helper use that setup. The other four define their own: menuz's `macos.bats` and `menuz.bats`, `install_e2e.bats` and `install_guards.bats`. None of those four runs unison, gpg, osascript or a clipboard tool.

Owner dc. vc routed it on 19 Oct 2026 from dc's slot 83 findings, for 2.14.1, ahead of the Linux issue, since every run adds debris.

## Design

dc, 19 Oct 2026, at `2d73b7f`. Size: S. The suites test the same things, and keep their state in their own dirs.

1. **The helper keeps unison to the test.** `isolate_tool_homes`, in `test_helper.bash`, is called by `setup()` (`:60`) once the per-test dir exists, and exports `UNISON="$BATS_TEST_TMPDIR/unison"`. unison makes that dir itself and keeps its archives, its log and its `default.prf` there. The per-test dir's removal (`:74`) then takes them all, and no user preference reaches a test.
2. **gpg fails closed, and a test that needs it makes a short home.** `isolate_tool_homes` also exports `GNUPGHOME=/nonexistent/utilz-test-gnupg`, a path that cannot be created, so a test that runs gpg without a home of its own fails by name rather than reaching the user's keyring. `make_gpg_home`, in the helper, makes `mktemp -d /tmp/utilz-gpg.XXXXXX`, writes `pinentry-program /usr/bin/false` into its `gpg-agent.conf` so a mistake fails instead of opening a dialog, exports GNUPGHOME, and records the home in `UTILZ_GPG_HOME`. When that is set, `teardown()` runs `gpgconf --homedir "$UTILZ_GPG_HOME" --kill all` and removes the home, before it removes the per-test dir. So a test that never ran gpg spawns nothing. The home sits in /tmp, not in the per-test dir, because gpg-agent cannot start at the per-test dir's depth on macOS (measured above). Under a home of its own, gpg's agent, and dirmngr if a network feature is used, run outside systemd and outlive the test unless ended (vc, 08:08Z).
3. **HOME is not changed,** for any suite. A global change would move rustup's and cargo's homes, which the prez and install suites need. The helper's header carries the rule beside 0016's "NO TEST REACHES THE NETWORK" (`:27`). No test writes outside its own temp dirs. A suite with its own `setup()` that runs unison or gpg calls `isolate_tool_homes` itself. A test that runs gpg calls `make_gpg_home`.
4. **cryptz's round trip becomes real, and local.** The round trip (`:112`) calls `make_gpg_home`, makes a throwaway key there with no passphrase (`gpg --batch --pinentry-mode loopback --passphrase '' --quick-gen-key ...`), sets `CRYPTZ_EMAIL` to it, and then encrypts and decrypts with stdin closed. That runs on every machine, with no pinentry, no network lookup (the key is local) and no user key. It asserts both halves and the text it gets back. Today it asserts nothing about the encrypt (`:126`). The skip on `gpg --list-keys` (`:119`) goes, and so does the `CRYPTZ_TEST_DECRYPT` opt-in with its comment (`:129` to `:142`), since the prompt it guards against cannot arise any more.
5. **macoz's background tests assert the call, not the wallpaper.** The three tests put a stub `osascript` first on PATH, in the test's own dir. It records its arguments and exits 0. Each test then asserts the recorded script names the expected picture: the given file for `:88`, and a seasonal image for `:67` and `:111`. Today they assert nothing on success.
6. **clipz's tests use a file-backed clipboard.** Stubs for `pbcopy` and `pbpaste`, and for `xclip`, `xsel`, `wl-copy` and `wl-paste`, go first on PATH in the test's own dir, all backed by one file there. The round trip (`:87`) then proves the dispatch on either platform without touching the user's clipboard. On Linux it also gives clipz a suite that needs no display, which the Linux issue's roster can take.
7. **The checks, red first on main.** They are written against the suites' behaviour, so they fail on main's code for the leak itself, not for a helper that does not exist yet.
   - In `syncz.bats`, one test runs `syncz --bidi --backend unison` as the suite's unison tests do, with HOME pointed at a scratch dir inside the test's own. The scratch dir holds `Library/Application Support`, as a real macOS home does, since without it unison exits 3 rather than write. The test asserts:
     - nothing was written under that HOME (no `.unison`, no `Library/Application Support/Unison`);
     - the archives are under `$UNISON`.
     On main the first assertion fails.
   - In `cryptz.bats`, one test runs the round trip with HOME pointed at an empty scratch dir. It asserts:
     - no `.gnupg` appeared under that HOME;
     - after the helper's teardown step for gpg, no process names the test's gpg home.
     On main gpg makes `.gnupg` under the scratch HOME.
   - macoz's and clipz's items carry their own proof, since each asserts the stub's record, which the real tools never write.
8. **Docs.** The helper's header (item 3). One paragraph in `docs/developer-guide.md`'s Test Best Practices (`:525`): a test keeps unison, gpg, the clipboard and the desktop to itself. One CHANGELOG line under Fixed.
9. **Versions.** None, since no utility's code changes.
10. **Runs,** each booked with gtools-vc:
    1. The new checks, red on main's code and then green, under bash 3.2 (`/bin` first on PATH) and bash 5, in a worktree.
    2. The four suites under both bashes, then the whole estate, since the helper is everyone's.
    3. kovacs's loop, the Linux proof, where the find over its home must show nothing new and no dirmngr may start.
    4. The test files sit outside CI's shellcheck collector, so they get dc's advisory pass under 0.9.0.

### Amendments

vc approved the design on 19 Oct 2026 (08:23Z), read against the code, with these three amendments and one option. Items 5 and 6 stay in this issue: they are the same class, and every run of those suites changes hv's wallpaper and clipboard. The fail-closed GNUPGHOME stays: it is No Silent Errors applied to tests.

11. **No gpg lookup can reach the network, even by mistake (A).** `make_gpg_home` writes a `gpg.conf` carrying `auto-key-locate local` and `no-auto-key-retrieve`, beside the agent's `pinentry-program /usr/bin/false`, as the helper's 0016 rule asks. The throwaway key uses a reserved domain (`utilz-test@example.invalid`) and gpg's quick default for its algorithm (`future-default`), so its generation costs CI nothing.
12. **teardown's kill is not silenced (B).** When `gpgconf` is missing, or `--kill all` fails, teardown says so on stderr, naming the home, and still removes it. A leaked agent is named, never hidden.
13. **clipz's tests pin XDG_SESSION_TYPE (C).** On Linux, one test runs with `x11` and one with `wayland`, so the runner's own session cannot choose which stub answers.
14. **The fail-closed path names its fix (D, taken).** The path is `GNUPGHOME=/nonexistent/utilz-test-gnupg-call-make_gpg_home`, so gpg's own error tells the next author what to do.
15. **The red run touches no real state (dc).** On main's code, the red phase runs only the two new checks, with `bats --filter`, each under its scratch HOME. It never runs the whole suite, which would write hv's real unison dir. vc moved the 2830 test archives out at 08:21Z, leaving hv's 26, so any stray write there would show.

**From critic-shell's read and vc's approval (19 Oct 2026):**

16. **The round trip's process check has its control.** Before the helper's teardown step for gpg, `pgrep -f <home>` must find the agent the decrypt has just used. After it, the check retries for up to 5 seconds while a process still names the home, since gpgconf asks the daemons to stop and does not wait for them, and then requires none.
17. **No teardown step is silent.** `end_gpg_home` reports a failed removal of the home on fd 3, beside a failed kill. `make_gpg_home` records the home straight after `mktemp`, so teardown removes it even when a later step fails. `isolate_tool_homes` clears any `UTILZ_GPG_HOME` a test inherits.
18. **No test signs with the user's key.** `isolate_tool_homes` adds `commit.gpgsign=false` and `tag.gpgsign=false` through `GIT_CONFIG_COUNT`, after any entries the environment already carries. It overrides only those two keys, so the user's name, email and the rest of their config still apply, where `GIT_CONFIG_GLOBAL=/dev/null` would drop them. Its check, red first on main, is `opt/utilz/test/isolation.bats`: a global config that turns signing on and names a stub that records and fails as `gpg.program`, so no real gpg is asked. A fixture commit and an annotated tag must both succeed without calling it.
19. **clipz.bats's stdin test passes the bin path as an argument,** so a path with a space survives.
