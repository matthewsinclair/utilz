## What

`run_doctor`'s utility check (`[5/7]`) says "Found N utilities, all properly configured" in two cases where it has read no yaml.

- **A utility with no yaml.** `[5/7]` checks that each utility's implementation is there and executable, then reads its `utilz_version` through `get_util_metadata`. With no `<name>.yaml` the reader answers 1, which `[5/7]` takes as no requirement, so the utility passes. `[6/7]` skips a utility with no yaml (`opt/utilz/lib/common.sh:861`). So doctor names it nowhere and counts no issue, while `utilz <name> --version` says `version unknown - missing <name>.yaml`.
- **No yq.** `[5/7]` skips every version check when yq is missing (`:800`) and still calls every utility properly configured (`:833`). `[6/7]` names yq as missing, so the run is not silent, but `[5/7]`'s verdict claims a check it did not make.

0081 stops `[5/7]` calling a yaml it cannot read properly configured. These are the two other ways the verdict says more than the section read. critic-shell saw both in its review of 0081, and cc files them on vc's word (19 Oct 2026), low, for 2.14.1, after 0084.

## Fix, for the design to settle

`[5/7]` lists a utility with no yaml among those with issues, `<name> (no <name>.yaml)`, and counts it, since no other section does. When yq is missing, `[5/7]` says its version checks did not run and calls no utility configured, while `[6/7]` keeps the count for yq. The no-yq test needs 0084's `path_without` to hide yq, so this lands after 0084, built on 0081's `[5/7]`. Size: XS.

## Design

cc, 19 Oct 2026, at `9bb32fa`, on 0081's `[5/7]` and 0084's `path_without` and `run_without_yq`. Size: XS.

1. **A utility with no yaml is an issue of `[5/7]`'s.** After the implementation checks, and before the yq branch, `[5/7]` asks `[[ -f "$(util_yaml_path "$name")" ]]`. A utility without one joins `broken_utils` as `<name> (no <name>.yaml)` and goes no further, so it is listed under "Found N utilities, M of them with issues" and counted once, by `[5/7]`, since `[6/7]` skips it (`common.sh:947`). It is asked before the yq branch, so a missing yaml is named with or without yq. `get_util_metadata` keeps its status 1 for no yaml; `[5/7]` no longer reaches it then.
2. **Without yq, `[5/7]` says what it did not check.** The loop still checks each implementation, and each yaml's presence by item 1, and then skips the version read as today. After the loop, where yq is missing and there are utilities, it warns `utilz_version is not checked without yq: <N> utilities, yq counted by [6/7]` and never prints "all properly configured". That line counts no issue, since `[6/7]` already counts yq. A broken utility is still listed and counted as today.
3. **One new test and one extended, in `opt/utilz/test/common_lib.bats`, each red first on 0084's code.**
   - New, beside 0081's `[5/7]` test: "run_doctor's [5/7] names a utility with no yaml and counts it (issue 0087)". The fake home without `beta.yaml`: doctor lists `    - beta (no beta.yaml)`, does not say "all properly configured", and counts one issue more than the fake home with it. Red on main at the listing line.
   - Extended: "run_doctor() completes without yq and names it as missing" already runs doctor on this tree through `run_without_yq`, which 0084 puts on `path_without yq`. It gains two assertions, marked for 0087: the output says `utilz_version is not checked without yq`, and does not say "all properly configured". Red on main at the first of them. A second test of doctor without yq would repeat its setup.
