## Summary

`utilz install` neither builds nor ships the `showreel` binary, and the shim's install branch does not notice. **An install published from any commit since `b8dc9f1` (ST0017/WP-05) hands `prez showreel <...>` to a file the publish never produced.** Found by cc on 2026-09-14 while fixing issue 0023, which touches the same shim; hv read it as a defect the same day.

Three sites, each necessary:

- **The build produces only the root package.** `opt/utilz/lib/install.sh:485-495` runs `cd "$crate" && cargo build --release --quiet`, with no `--workspace`. The workspace (`opt/prez/crate/Cargo.toml:62-63`) declares `members = ["crates/artifact", "crates/showreel"]` and no `default-members`, so a build in the root builds prez and what prez links, and never showreel. The shim's own build carries `--workspace` for exactly this reason (`opt/prez/prez`, the comment above its `cargo build`: "without it the shim's build-on-first-use can never produce a member crate's binary at all").
- **The owned set names only prez's binary.** `install.sh:25` defines `INSTALL_PREZ_BINARY="opt/prez/crate/target/release/prez"`, and `install.sh:112-120` adds it and `INSTALL_PREZ_VERSION_FILE` to the owned set. No other path under `target/` is ever published.
- **The install branch checks one binary of two.** `prez_ensure_built`'s install branch returns 0 when `$BINARY` alone is executable. The source branch has read a missing showreel as a stale tree since WP-05 ("a missing sibling is a stale tree, not a fresh one"), and the install branch was not given the same rule. The shim then reaches `exec "$SHOWREEL_BINARY" "$@"`.

## What happens

**Derived from the code path, not observed:** publishing is a real act, and `utilz install` refuses a dirty tree. `exec` of a missing file makes a non-interactive bash exit with its own "No such file or directory" rather than a named refusal, so an installed `prez showreel check <dir>` fails with no remedy in the message.

**Latent today, live on the next publish.** The install at `~/Devel/opt/utilz` was cut from `b6ca749`. Its shim has no handover (0 occurrences of `prez_is_handover`) and its `target/release` holds only `prez`, so `prez showreel` there reaches the prez binary and is refused in prez's own grammar. The next `utilz install` or `utilz upgrade` from `main` ships a shim that hands over and no binary to hand over to.

## Why nothing caught it

The install guards measure the install against its own owned set, and the owned set is where the omission is. `prez showreel` is exercised from the source tree, where the shim's `--workspace` build always produces both binaries.

## Severity

Medium. A shipped command fails on every install published from current `main`, with a bash error in place of a refusal. No current install is affected.

## Fix direction, for hv to rule on and schedule

Build with `--workspace` at publish time, add showreel's binary to the owned set beside prez's, and give the install branch the source branch's rule: a missing showreel is refused by name, as a missing prez already is. The Done includes a test that the owned set names both binaries, red against the current owned set.

## Resolution, 2026-09-14

Fixed by cc, the finder, at `2e96e2a`, along the fix direction above. `install.sh` builds with `cargo build --release --workspace`, the owned set names showreel's binary beside prez's, and the shim's install branch refuses a missing binary by name, printing the expected path of each one that is missing. Four tests came with the fix: the owned set names showreel's binary, the stub cargo is asked for the whole workspace, an installed `prez showreel` reaches the showreel binary the install shipped, and the installed shim refuses by name when showreel is missing.

Verified by vc, the reviewer. Red first, replayed independently against the pre-fix code at `387e377`, whose `opt/` is identical to that of `2e96e2a`'s parent: exactly the four new tests failed, each on its own assertion, 2 of 24 in `install_lib.bats` and 2 of 22 in `install_guards.bats`. Green at `2e96e2a`: 24/24 and 22/22. No fourth site: no other install or shim path names prez's binary without showreel's. CI at `4e2b3b5` ran all four on both Test on macOS and Test on Ubuntu, and passed them. Closed by vc, the reviewer, not the fixer.
