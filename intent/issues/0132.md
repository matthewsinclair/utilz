## What

rhadamanth-sysadm, 2 Nov 2026, at hv's request, to utilz-vc (received after the estate read stamped 07:06:24Z and before vc's date -u of 07:07Z): `arngz apply` exits 1 when an app in the desk is running but has no window it can see, even though nothing failed.

utilz 2.14.8, arngz 1.1.2, on rhadamanth (macOS, the Hammerspoon engine; `arngz doctor` passes all 7 checks). apply reports each entry as placed, skipped, unseen or failed. An app that is running with no standard window on a desktop space (closed, minimised, or a `window` pattern that matches nothing at that moment) is reported `unseen`, and that alone makes apply exit 1. So a desk that is fully in place reads as a failure whenever any app it lists has no window open, which on a desk of about 20 apps is most of the time. menuz runs `arngz apply <desk>` from its Desks menu, and nothing that scripts arngz can tell "desk applied" from "something broke".

Repro (Molt-matts `config/arngz/desks/zeopit.yaml` at 9adb5ae): with Ivory, Screen Sharing and Console running and no window of theirs open, and Finder's "Downloads" window closed, `arngz apply zeopit` reports every other app `placed`, and those four `unseen`, eg:

```text
com.tapbots.Ivory (displays[0].spaces[1].apps[2]): unseen: com.tapbots.Ivory is running and no standard window of it on a desktop space could be named (a full-screen window is left alone, and one Accessibility cannot name is not seen)
```

Exit status 1.

## Measured

By reading, at main's head 1c48b5e3, where arngz's files are as at 2.14.8's tag:

- `P.apply_report` (`opt/arngz/lib/plan.lua:985`) sets exit 1 for every entry that is not placed (`:1026` to `:1030`), whatever its outcome, and its comment (`:982` to `:984`) and the shim's on `cmd_apply` (`opt/arngz/arngz:1459` to `:1464`) say so: 1 when any is skipped, unseen or failed. The engine's `execute` performs nothing for an `unseen` op (`opt/arngz/lib/arngz.lua:941`, `REPORT_ONLY`), so apply changes nothing for such an entry and still exits 1.
- `cmd_diff` (`opt/arngz/arngz:1557`) exits 1 when the plan holds any op at all (`:1563` to `:1567`), and an `unseen` op is one (`plan.lua:559` to `:568`). So `diff` says the machine differs where `apply` would change nothing, against the help's own account of diff's exit as whether anything would change (`help/arngz.md:110`, `:241`). The same windowless app makes both verbs exit 1.
- `plan_test.lua:833` pins today's apply exit ("an entry no window matched is unseen, exit 1"); no bats test pins `unseen` on either verb.

## Fix

1. An `unseen` entry is said and counts against nothing: `apply` exits 0 when every entry is placed or unseen, and 1 when any is skipped or failed, or when any op failed whatever entry it served, as today.
2. `diff` exits 1 when the plan holds any op but `unseen`, and 0 when it holds none, so it agrees with `apply`.
3. Both print every unseen line as today, since a pattern that matches nothing is worth seeing.
4. Not in this fix, each hv's to ask for: a `--strict` flag keeping today's exit, which the report offers only if one is wanted; and `skipped` (not installed, or not running under `--no-launch`), which keeps exit 1.

## Design

utilz-vc, 2 Nov 2026, each file:line read at main's head 1c48b5e3. Size: S.

1. **apply.** In `P.apply_report` (`plan.lua:1026` to `:1030`), an entry whose outcome is `unseen` leaves `code` as it is: the `else` that sets `code = 1` becomes `elseif outcome ~= "unseen"`. The comment at `:982` to `:984` gives the new contract and its reason: a running app with no window to name has nothing to arrange. Nothing else in the report moves. An `unseen` outcome means nothing failed for that entry, since a `failed` result overrides `unseen` and never the reverse (`:1017`). A failed phase still exits 1 through its own line (`:1037` to `:1038`), so a desk whose every entry is unseen cannot hide a phase that failed.
2. **diff.** `cmd_diff` (`arngz:1563`) counts the ops that are not `unseen`, `yq '[.ops[] | select(.op != "unseen")] | length'`, and its comment (`:1554` to `:1556`) says an unseen entry is said and counts against nothing, as `P.apply_report` counts it. The rule has two homes because the two exits are made in two places, apply's by the engine from what execute returned and diff's by the shim from the plan, so each comment names the other. The engine is loaded by `dofile` from beside the shim at every call (`arngz:377`, `arngz.lua:1409`), so shim and engine cannot come from two installs.
3. **The shim's comment** on `cmd_apply` (`arngz:1459` to `:1464`) reads 0 every entry placed or unseen, 1 any skipped or failed.

## Design, amended after critic-lua's and critic-shell's reads

utilz-vc, 2 Nov 2026, before the landing. Both reads (critic-lua: 0 critical, 3 warning, 5 recommendation, 1 style; critic-shell: 0 critical, 3 warning, 2 recommendation) found that the design above let too much through and kept the rule in two homes. Amended:

1. **An unseen op still counts while a window read failed.** plan adds every read failure (a window record carrying `read_error`, a window id read that failed, the window filter failing) to every unseen reason (`plan.lua:435` to `:443`), since the window not read may be the entry's. So plan marks an unseen op `uncounted` only when none failed, and that mark is the rule's one home: `P.apply_report` and `P.plan_exit` read it, and execute copies it onto the result beside `r.bundle` (`arngz.lua`).
2. **In apply, an entry whose app this apply launched counts unless it was placed.** The launch changed the machine, and exec_launch reports done only once it has seen a claimable window (`arngz.lua:377`), so an entry it then finds unseen is not one with nothing to arrange.
3. **apply's exit is counted from every result,** not from the one outcome the line shows: a result that is not done and not marked uncounted counts, and so does a blanket failure on a placed entry. Today's engine cannot put an unseen and a skipped on one entry, but the exit no longer depends on that.
4. **diff's exit comes from the engine's plan:** `P.plan_exit(ops)`, beside `P.plan_report`, returned by the plan verb as `exit` (`arngz.lua`, VERBS.plan; mirrored in `opt/arngz/test/discover_response.lua`). `cmd_diff` reads and checks `.exit` the way `cmd_apply` does, and refuses, exit 2, with the response kept, when the plan cannot be printed or its exit is not 0 or 1. So the shim names no op kind, and a yq failure no longer reads as a difference.
5. **Tests.** plan_test.lua checks the mark on a clean unseen and on one beside each of the three read failures, and `P.plan_exit` on an unseen alone, beside a place, and on no op. For apply's report it checks an uncounted unseen (exit 0), a counted one (1), a failed entry before and after an uncounted unseen (1), a skipped result after an uncounted unseen on one entry (1), a failed launch then unseen (reads failed, 1), a done launch then unseen (1), and every entry unseen beside a failed phase (1), its premise asserted and the phase line found from the end. arngz.bats adds diff counting an unseen planned while the window filter failed (exit 1), and diff refusing a plan with no exit (exit 2).
6. **Docs.** help/arngz.md and the CHANGELOG say when an unseen entry still counts, and that diff's exit comes from the engine's plan.
7. **Runs,** booked as one: the first run (slot 01M6DJFNM9BX56TZSAYC74JT8K, on the design above) was green and is superseded; the amended bytes run again, red at 52b29cc2 plus the tests, then green in the primary (slot 01M6DKJ7V1JBQRCW3Y2WVEFKT1).
