## What

hv, 18 Oct 2026, on menuz's menu as it stood: "We need a dividing line under the version string. And then the desks section needs to be "Desks...  >" (ie a flyout) and in the flyout are the list of desks that are known about. Also, "Discover arrangement" should just be "Discover...". And we should have a "Utilities" menu with a flyout that has Hammerspoon, Log, etc. Basically, tidy up the menu, favour single word menu items, make sections with flyouts, and group similar things together. The customisable bit (ie where the commands are done) should be in its own section. If this can all be done from the menuz config file, then great." Later that morning, looking at the tidied menu: "I think 'Machine' doesn't need to exist and the contents of Machine can be in Utilities, right?"

Most of it is the menu file's to do, and hv's file does it now. Two parts the file cannot do:

- **A line under the identity row.** `MenuBuilder.build` adds the row and goes straight on to the refusals and the file's entries. Gtools.app's menu has a separator there.
- **Log, Edit Menu… or Reload in a flyout.** They are the fixed tail (`MenuSpec.tail`), below every file's entries. A file item can open the log, since `MENUZ_LOG` is in a run's environment, but the tail's Open Log would still show beneath it, so the log would be in the menu twice.

## Measured

18 Oct 2026, against the installed 0.1.0 (069e0f38). A file with `Desks…` as a submenu holding the `each`, `Discover…` as an item, and `Utilities` as a submenu validates. `menuz render` lists the desks under `Desks… >`, since the builder and the realiser both recurse into submenus. The running app reloaded it on write and passed it.

## Fix

1. A separator under the identity row, in the menu and in `menuz render`'s outline.
2. A `menuz:` entry places one of the app's own items from the file: `menuz: log`, `menuz: edit` or `menuz: reload`, each at most once, anywhere in the menu. The tail keeps whatever the file leaves out, and Quit menuz never moves, so a file that never loaded still shows all four.
3. Single words for the app's own items: Log ("Log (no log yet)" while there is none), Edit… and Reload; Quit menuz is unchanged.
4. A run's form takes its item's label without a trailing ellipsis as its window title, so `Discover…` opens a form titled Discover.

The shipped example becomes the tidied menu, so `menuz init` writes it, and `help/menuz.md` describes all four.
